# VCard Native V1.2.1 — Maintenance Requirements

**Status:** Product direction agreed in conversation; implementation not authorized.  
**Baseline:** V1.2.0, versionCode 3, signed APK verified. GitHub publication not confirmed.  
**Scope:** UI/UX corrections to the existing single-profile app. Multiple Profiles remains V2.0.

## M1 — Country calling-code selector

- Replace the excessively tall country-code popup with a field-anchored dropdown following the existing **Social Profiles → Platform** selector's visual language.
- Position below the field when space permits, otherwise adapt to visible screen/IME bounds.
- Constrain menu height and enable scrolling through the entire country list.
- Preserve existing country labels, dialing codes, selection, validation, persistence, and accessibility.
- Do not change the Social Profiles selector or contact export semantics.

## M2 — Quick Card Widget responsive content

- Keep the **single stored professional title**; do not create a widget-only title, alter profile data, or abbreviate the stored value.
- Choose presentation using actual widget width **and** height; launcher grid dimensions are illustrative, not guaranteed dp measurements.
- When resized, update the appropriate layout without requiring widget removal/re-addition.
- Preserve profile photo (initials avatar only as existing no-photo fallback), name, menu actions, accent and theme behavior.
- Prioritize identity and controls, prevent clipping/overlap, and use ellipsis only when the allocated text space is exhausted.
- In **2×1**, render professional-title initials, e.g. `Solution Engineer` → `SE`, `Senior Solution Engineer` → `SSE`. Existing all-capital acronyms such as `CTO` should remain recognizable. Details for punctuation, stop words, single-word titles, non-Latin text, and maximum initials length require design/technical confirmation.
- In other sizes, display the actual title, wrapping as height allows.

### Proposed grid-size behavior (subject to actual device measurements)

| Grid | Display proposal |
|---|---|
| 2×1 | Photo, name, **title initials**, overflow menu; protect all elements from collision |
| 2×2 | Centered identity, full title up to 2 lines if space allows |
| 3×1 | Horizontal identity, full title on one line with ellipsis if needed |
| 3×2 | Identity, full title up to 2 lines if space allows |
| 4×1 | Horizontal identity, full title on one line if possible |
| 4×2 | Larger identity, full title up to 2–3 lines if space allows |
| 4×3 | Larger typography, full title with additional wrapping if space allows |
| 4×4 | Spacious layout, show as much of full title as available height permits |

**Important:** These eight rows are proposed responsive scenarios, **not** eight verified implemented widget configurations. Preserve existing VeryNarrow/Compact/Standard/Expanded size classes unless a separately approved implementation plan justifies adjustments.

## M3 — Existing widget defects

- Eliminate avatar/menu overlap at minimum Standard width.
- Eliminate Expanded text clipping at large font settings.
- Refresh widget text/layout after relevant font-size or profile/appearance changes, subject to platform update behavior.

## Out of scope

Multiple Profiles (V2.0), new card styles or accent colors, new widget profile fields, new widgets/actions, cloud/backend, signing or application ID changes, data-schema migration, unrelated UI redesign.

## Acceptance direction

Country list scrolls and selects correctly; widgets remain legible and controls usable at representative sizes and font scales; 2×1 initials derive from full stored title; resizing changes presentation; V1.2 profile, sharing, QR and widget actions remain intact. Exact test matrix awaits source/device inspection.
