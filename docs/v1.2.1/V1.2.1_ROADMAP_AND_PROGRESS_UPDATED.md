## Country-code dropdown (M1) — implementation record, 2026-11-05

- **Implemented:** `PhoneCountrySelector` in `ProfileScreens.kt` now uses a read-only outlined country anchor styled to match Social Profiles → Platform. A focusable `DropdownMenu` contains a search field above a height-bounded scrolling results list.
- **Supporting changes reported:** `PhoneNumbers.filterRegions` in `PhoneNumbers.kt`, one new filter test in `PhoneNumbersTest.kt`, and `phone_country_search` / `phone_country_no_results` strings in `strings.xml`.
- **Display:** selected value is compact, e.g. `+44 GB` or `+880 BD`; results show localized full labels such as `United Kingdom (+44)`.
- **Search:** country names, calling codes with or without `+`, and ISO region codes; case- and diacritic-insensitive. Search resets when dismissed or a country is selected. Opening hides the existing keyboard; tapping the search field allows typing.
- **Preserved by implementation scope:** existing ISO-region selection callback and persisted profile format, phone validation/E.164, contact export, Social Profiles selector, Quick Card widgets, Gradle, manifest and signing configuration.
- **Reported verification:** `:app:compileDebugKotlin` succeeded; focused `PhoneNumbersTest` suite passed **4 tests, 0 failures**. These are Codex-reported results, not independently rerun here.
- **Owner review:** owner reviewed screenshots of search results and the compact country field, then approved the UI. A screenshot showed active phone validation for a selected region.
- **Not claimed:** full regression testing, Android Studio Sync, or exhaustive keyboard, TalkBack, font-scale, bottom-edge and stacked-layout device checks. Do not infer these from screenshot approval.

## Adaptive Quick Card widget (M2/M3) — investigation record, 2026-11-05

- **Status:** read-only investigation completed. No widget source files modified; no builds or tests performed for this investigation.
- **Architecture:** one `QuickCardWidgetProvider` and updater; Android 12+ responsive `RemoteViews(Map<SizeF, RemoteViews>)`; four logical size classes share three XML layouts.
- **Current reported breakpoints:** VeryNarrow **120×48 dp** (compact XML), Compact **180×48 dp** (compact XML), Standard **120×160 dp** (standard XML), Expanded **260×120 dp** (expanded XML). These are internal breakpoints, **not** guaranteed 2×1, 2×2, etc. launcher measurements.
- **Current rendering:** stored professional title shown without abbreviation when enabled; one line in narrow layouts, two lines in Standard/Expanded, with existing font-scale restrictions. Avatar initials are derived separately from the name and cannot simply be reused for professional titles.
- **Known issues under investigation:** narrow Standard avatar/menu overlap; Expanded title clipping at larger font scales; line-limit changes may remain stale until widget refresh after configuration changes. Geometry and refresh explanations are source-based findings/hypotheses, **not verified device outcomes**.
- **Approved product direction:** 2×1 should display title initials (e.g. `Solution Engineer` → `SE`, `Senior Solution Engineer` → `SSE`) without modifying the stored title; larger widgets should show the full title to the extent space allows, adapting to both width and height. Preserve photo, name, menu, appearance and existing functionality.
- **Next investigation:** obtain actual widget width/height measurements on the target launcher for representative 2×1 through 4×4 grid arrangements, then propose minimal policy changes. Do **not** assume that only the VeryNarrow class corresponds to 2×1.
- **Decisions pending:** initials handling for hyphens, slashes, acronyms, single words, non-Latin titles and very long titles; revised thresholds and extra size-map entries; refresh strategy. Any manifest change needs separate approval.
