# VCard Native V1.2.1 — Country Calling-Code Dropdown Final Implementation Plan

**Status:** Planning complete; **implementation requires separate owner authorization**. Baseline: V1.2.0. Milestone: M1 only. Based on two read-only Codex reports, including final technical review dated 2026-11-05. No runtime popup verification performed.

## Source findings (reported by Codex)
- `ProfileScreens.kt`: `PhoneCountrySelector` ~726 currently uses `OutlinedButton` + plain `DropdownMenu` without search or app height cap. `PhoneFieldEditor` ~664 arranges country/phone fields side by side with weights 1.1/1.9 (country ~37%), or stacked at font scale >=1.35 or width <460dp.
- `SocialPlatformDropdown` ~1175 uses `ExposedDropdownMenuBox`, read-only `OutlinedTextField`, `menuAnchor(MenuAnchorType.PrimaryNotEditable)`, 12dp shape, theme styling, and keyboard dismissal.
- `PhoneNumbers.kt`: `PhoneRegion(isoRegion, countryName, callingCode)`, `selectorLabel` with full name and code; list generated via libphonenumber and locale sorting. Repeated calls can be avoided with Compose `remember`, with locale changes handled correctly.
- `ProfileViewModel.kt`: `selectPhoneRegion` accepts ISO region; leave it unchanged. Persistence/validation/contact export depend on this identity.
- Reported project versions: Compose BOM 2025.04.01, Material 3 1.3.2, compileSdk 36, minSdk 31, `adjustResize`, edge-to-edge.
- The report could not inspect the Material 3 sources JAR. Popup focus and IME claims are hypotheses requiring device verification.

## Approved user-facing behavior
1. The selected country control visually matches the existing Social Profiles platform outlined field, while remaining within the existing phone editor layout.
2. **Compact selected value**: `+44 GB` (calling code + ISO region), not the long full country name. In dropdown results, show full localized labels such as `United Kingdom (+44)`. Preserve accessibility access to the full selected country name.
3. Menu opens **without auto-focusing search**, hides any previous keyboard and clears previous phone-field focus as appropriate.
4. A visible **search field within the popup** accepts intentional typing; full country list scrolls without search. Search field remains visible while list scrolls.
5. Filter by localized country name and calling code (including `+` prefix). Case-insensitive and trimmed. Consider ISO code and diacritic-insensitive matching as optional enhancements pending owner confirmation. Empty query restores all entries; no matches shows an accessible message. Preserve original localized sort and do not auto-select.
6. Selecting a result calls existing `onSelect(country.isoRegion)`, closes popup, clears query, hides IME. Dismiss/back/outside tap closes without changing selected region and clears query.
7. Popup must be height-bounded, scrollable, usable at bottom edge, with IME and large font sizes, and on resizing/stacking.

## Smallest safe implementation proposal (for Codex to verify, then implement only after approval)
- In `ProfileScreens.kt`, preserve `PhoneCountrySelector` signature/call sites. Replace button with read-only outlined anchor modeled on Social Profiles. Keep `expanded` and transient `query` states separate. Cache country options with locale-aware invalidation, rather than regenerating during every recomposition.
- **Popup focus decision:** A search field inside `ExposedDropdownMenu` may not receive IME focus in this Material 3 version. Verify experimentally. If it fails, use a focusable anchored `DropdownMenu` or equivalent popup while retaining the exposed-style anchor. Do not silently switch to a non-anchored Dialog/BottomSheet; seek approval if anchoring cannot be preserved.
- **Bounded list:** Keep search input pinned above a bounded scrollable results area. If using `LazyColumn` within `DropdownMenu`, ensure a finite height constraint; avoid unbounded nested vertical scrolling/measure exceptions. Use device-tested height and width behavior, not a guessed hardcoded universal size.
- **IME:** On initial open hide existing keyboard, clear old focus as needed; do not auto-focus search. On tap, search can focus and show IME. On close/selection clear query and dismiss keyboard appropriately. Validate first Back press behavior.
- **Semantics:** Label country control and search input, mark selected result, preserve readable touch targets and full selected-country accessibility text.
- `android/app/src/main/res/values/strings.xml`: add accessible search-field label and no-results text (and any necessary localized equivalents). Confirm exact project resource path before editing. Avoid hardcoded user-facing strings.
- Optional: pure search helper in `PhoneNumbers.kt` and focused test in `PhoneNumbersTest.kt` **only with explicit approval for extra files**. No changes to `ProfileViewModel`, `ProfileCodec`, `ProfileValidator`, `ContactExport`, Gradle, manifest, schema, signing or Social selector.

## Known risks / gates
- Focusable popup may differ from exposed popup in width/elevation; match anchor width where technically possible, without obscuring phone input. Confirm real device behavior.
- Full country labels must remain visible in results even if compact anchor displays `+44 GB`.
- Search by `+1` matches multiple regions: retain all relevant entries and ISO identity; never collapse to calling code alone.
- Locale changes, empty results, screen edge, large font, IME resizing, accessibility and search dismissal need focused checks.
- **No implementation until owner approval and project-protection-required verified timestamped external backup.** Report exact files and diff; stop if additional changes become necessary.

## Targeted acceptance checks (not yet run)

3. Scroll full list with search pinned; select a filtered result: ISO region correct and persists; phone parsing and contact export unaffected.
4. Dismiss with outside tap/back; reopen: query empty, selected region unchanged. Check Back with IME visible.
5. Test side-by-side compact `+44 GB` and stacked layout, near bottom of screen, at large font scale; no clipping/overlap.
