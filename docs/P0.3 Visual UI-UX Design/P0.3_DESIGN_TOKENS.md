## 3. Contrast calculations and limits

Method: normalize each hex channel to sRGB 0–1. For channel c, linearize as c/12.92 when c <= 0.04045, otherwise ((c + 0.055)/1.055)^2.4. Relative luminance L = 0.2126 R + 0.7152 G + 0.0722 B. Contrast = (larger L + 0.05)/(smaller L + 0.05). Values below were computed locally and rounded to two decimals; comparisons use unrounded values.

Use >=4.5:1 for all text in this specification and >=3:1 for meaningful non-text indicators against adjacent fills. These conservative text checks and non-text checks follow the contrast principles in [WCAG 2.2](https://www.w3.org/TR/WCAG22/#contrast-minimum), including [non-text contrast](https://www.w3.org/TR/WCAG22/#non-text-contrast). They are design references, not a claim of app or legal conformance.

| primary / surface | 9.82 | 6.74 | Links/icons/focus foreground >=4.5 |

Do not use low contrast as the only explanation of an unavailable action. Recheck composited states before implementation/release; actual screen-reader, low-vision, large-text and QR scanning tests remain later work.

## 4. Typography

`type.family = Android system sans-serif`, with Roboto where provided; actual glyph rendering/fallback must be reviewed on the target Pixel. Weights are visual targets, not bundled-font/dependency decisions. Use sp for both font size and line-height intent, allow Android font scaling and content-driven height. No all-caps defaults, forced tracking or font-choice UI.

| Token | Size / line height | Weight | Usage |
|---|---|---|---|
| type.identity | 32sp / 40sp | 500 | N01 saved full name, wrapping |
| type.screenTitle | 24sp / 32sp | 500 | App bar/sheet title; allow multiline height |
| type.sectionTitle | 20sp / 28sp | 500 | Form/card section headings, D01 title |
| type.body | 16sp / 24sp | 400 | Bio, values, notices, instructions |
| type.input | 16sp / 24sp | 400 | Editable field value |
| type.supporting | 14sp / 20sp | 400 | Field labels/help/errors; errors may be 500 |
| type.action | 14sp / 20sp | 500 | Button/row actions |
| type.navLabel | 12sp / 16sp | 500 | Always-visible primary navigation label |

Essential privacy/restore explanations use body, not navLabel. No important content relies on a tiny caption. Text scale may grow independently of nominal dp spacing. Bold is not a replacement for semantic headings. Long names, localized labels and URLs wrap; no max-line clipping of essential values. These targets use [Android dp/sp and grid guidance](https://developer.android.com/design/ui/mobile/guides/layout-and-content/grids-and-units); actual fit is unverified.

## 8. Token governance and unresolved checks

P0.3-01–P0.3-12 are approved by the project owner following successful guideline reconciliation. All screens/components consume these role names; changing an approved token later should require updating documented pair checks and cross-screen review. No theme files, font files or app resources are generated. Contrast arithmetic is completed for listed pairs only; typography rendering, 200% font/display-size behavior, focus-ring compositing and real device fit are unresolved. Do not claim a tested design system or begin P0.4/P0.5 implementation from this specification.
