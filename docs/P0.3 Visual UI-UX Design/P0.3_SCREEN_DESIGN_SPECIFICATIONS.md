> **Owner-approved Milestone 1.10 refinements (2026-11-01):** Native Compose first-run setup is Welcome → Basic Information → optional Contact Information → Review → Create My Card, with a single A2 commit at the final action. With a saved profile, primary navigation is exactly **My Card | Share | Profile**; Share is the center tab and default destination, and the sole Version 1.0 card is Primary automatically. Share displays the export-enabled QR and “Scan to save my contact.” Preview Contact opens the existing read-only bottom sheet, styled with the selected theme/accent and showing only saved Contact Export-enabled values in labeled, icon-supported rows; values wrap and remain selectable, and the sheet scrolls at large text sizes while retaining Edit Sharing Settings and Done. Send Contact creates the existing FileProvider-backed vCard and opens Android’s native chooser directly. My Card presents saved, visibility-enabled contact values in readable, selectable rows instead of Call, Message, or Email buttons, and retains a dedicated Show QR presentation. The Profile hub groups Personalization and Data & Security; Advanced provides draft-backed Visibility & Sharing, Security & Encryption, Hosted Profile, and Profile Images routes. Appearance has a compact, noninteractive business-card preview that reacts immediately to the existing theme/accent palette without inserting an unsaved-status message or showing theme/accent text inside the card. Save Appearance stays in a stable bottom area, is enabled only for changed selections, and unsaved choices require confirmation before discard. Profile deletion is destructive-confirmation gated and removes local A2 data while leaving external backups untouched. These requirements supersede conflicting first-run, editor, navigation, Share, Appearance, and deletion notes below for Milestone 1.10, preserving the approved Sapphire identity, accessibility, existing data formats, and native-layout principles.
>
> **Owner-approved Milestone 1.10 phone-country refinement:** Onboarding Contact Information and the editor's Contact tab pair phone entry with an accessible country/region selector showing the selected country name and international dialing code. The initial suggestion uses the device locale only; no location permission is requested. Contact Export includes a default-on “Include country code when sharing” control and a live formatted-number preview. This preference changes phone formatting only, independently of My Card visibility and the phone's export-inclusion switch. Contact Preview, QR, and .vcf show the same selected international or national representation.

## Shared layout and behavior contract

**Owner-approved Milestone 1.11 Step 4E (2026-11-01):** Immediately after required Full Name, add optional First Name, Middle Name and Last Name in existing onboarding Basic Information and Edit Profile Details. Use existing outlined field styling, spacing, localized labels, validation/focus/error patterns and scroll frames; keep required Full Name and all navigation/tabs unchanged. Help explains manual components, no Full Name rewriting, and explicit Contact Export enabling. Review shows entered components. Each gets an independent default-off Contact Export switch in the existing Visibility & Sharing screen; no component-specific My Card switch because Full Name remains the card identity. Contact Preview displays only included components with separate labels. No new screen, destination, tab, card layout, or name guessing.

**Owner-approved Milestone 1.11 recovery/deletion exception (2026-11-01):** Preserve the approved Milestone 1.10 navigation, card, editor, appearance, sharing, and simple Delete Profile row/confirmation popup. No Danger Zone or multiple-card UI is added. An unavailable profile offers Retry Verification, Restore Application Backup when its recovery context can be established, and Cancel/Leave. The existing restore sheet distinguishes unavailable data from an empty profile and requires explicit "Recover from this backup" confirmation, explaining whole-profile replacement, private retained evidence, no automatic fallback, and storage implications. Invalid backups and canceled review leave existing state unchanged.

While a durable deletion/recovery intent is pending or operational evidence is malformed/contradictory, profile viewing/editing/export/replacement and new-profile creation are blocked. Use the existing scrollable screen frame for truthful pending/blocked feedback, Retry operation, and Cancel/Leave. Retry resumes only an already-confirmed valid intent; leaving does not cancel durable intent. Onboarding follows only verified deletion completion. New explanatory text and controls wrap/scroll at 200% font scale; normal dashboard and navigation styling remain unchanged. Do not describe logical deletion as secure physical erasure.

Nominal page gutter 20dp (16dp constrained), content max width 600dp, section gap 24dp and ordinary internal gap/padding 16dp. Dimensions grow for scaled text; system insets are additional. N01–N03 show C18 three-item labeled navigation; N04–N06 have Up and no primary bar. Primary bar and pinned action areas never cover scrollable content; add matching content padding. Use one vertical scroll owner per screen body where possible. The keyboard must not obscure focused fields/help/actions.

Buttons use visible labels and >=48dp targets; rows and app bars grow naturally. Every screen supports body/labels wrapping and direction-aware alignment. Decorative icons/images do not become independent screen-reader stops. Working copy below may be refined for tone without changing approved actions. Native E01–E04 activities are system-controlled external surfaces, not new app destinations designed here.

## N01 — My Card

**Hierarchy:** A premium business card is the focal point. Use C01 surface and C02 header, not a stack of settings groups. A short plain app bar identifies My Card; the card establishes visual character through cover, portrait, generous identity spacing and restrained depth.

Illustrative text schematic (composition only; not a rendered mockup):

```text
My Card                                      [top bar]
┌──────────────────────────────────────────┐
│ wide cover viewport                      │
│      portrait on opaque surface edge     │
│ Full name                                │
│ Professional title · Organization        │
│ Biography when shown                     │
│ Location · saved value                   │
│ Phone · saved number                      │
│ Email · saved address                     │
│ Website · saved URL                       │
│ Professional links / optional public key │
└──────────────────────────────────────────┘
Show QR                                      [primary action]
My Card [selected]     Share     Profile      [navigation]
```

- **Top app bar:** C17, My Card title, no Up or redundant edit/overflow menu. No Wallet/NFC icon.
- **Main content:** Cover 3:1, 88dp portrait, name in type.identity, title/organization in body with organization separated by line when needed; biography/location follow in body/supporting roles. Text sits on opaque surface. Optional empty sections collapse, including their gaps.
- **Contact information:** Display only nonempty, valid values enabled by saved Show on My Card settings; contact-export selection remains independent. Use compact icon/label/value rows for phone, email, website and location, with long values wrapping and selectable for copying. Do not launch dialer, messaging, or email while displaying the owner's card. Professional links may retain their explicit browser action.
- **Buttons/actions:** C04 professional links follow in a readable list. Conditional valid/display-enabled public-key Download public key uses a labeled row. Show QR is the filled primary action and opens the dedicated full-screen QR presentation without selecting Share. The outer card is not clickable.
- **Navigation:** C18, My Card selected; primary order is My Card | Share | Profile. Share is the center/default tab; Back from My Card returns to Share. No Home tab.
- **Spacing/alignment:** Card 24dp corners, 20dp internal identity inset, 24dp major group gaps; text/start anchors align. No absolute-position name/portrait overlap on narrow or large-text views.
- **Scrolling:** Whole card/action body scrolls above navigation; long names/bios and optional links remain readable. Never force the entire card into one viewport by shrinking text.
- **Empty/error:** No profile routes to guided N04, not a blank fake card. Missing imagery uses neutral fallback. Missing/hidden optional actions are absent. Missing handlers or failed public-key output uses C13 at caller; don't imply delivery.
- **Large text:** Identity and contact values wrap with no ellipsis; portrait enters normal flow and cover may be shorter. All essential data/actions stay reachable.
- **Semantics:** Name is a heading, identity block reads once, portrait is decorative when redundant, and contact labels/values are selectable. Website and professional links distinguish external opening. No image text is the only representation of identity.
- **P0.2 flows/components:** F02/F03/F04/F14/F15; C01/C02/C03/C04/C13/C17/C18. One profile only; no carousel, template or display-visibility shortcut that changes saved rules.

## N02 — Share

**Hierarchy:** Contact QR → concise offline description → Preview Contact and Send Contact. The white code panel is functional, not theme artwork.

```text
Share
Scan to save my contact.
              black contact QR on white
Preview Contact                             [read-only S01]
Send Contact                                [native chooser]
My Card              Share [selected] Profile
```

- **Top app bar:** C17 title Share, no Up. This is the center primary tab and the default destination for a saved profile.
- **Main content:** C05 contact QR panel and concise offline description. Generate QR from saved Contact Export-enabled fields. Preview Contact opens a read-only summary of only exported values; it does not create or share a file.
- **Buttons/actions:** Send Contact generates the .vcf from saved Contact Export-enabled fields and opens Android's native chooser directly. Preview Contact opens S01. Do not expose unavailable online-sharing or QR-image export controls.
- **Navigation:** C18 Share selected; a saved profile opens here by default. My Card is the left tab and Profile the right tab. Android Back exits from this default root. Show QR on My Card remains a dedicated presentation and does not select Share.
- **Spacing/alignment:** 20dp page gutter; code centered, remaining text start-aligned. Preferred panel 280dp, cap 320dp if room, additional white padding outside preserved quiet zone. Never tint/animate/overlay the QR or crowd it with adjacent controls.
- **Scrolling:** One body scroll; QR is not sticky over labels/actions. On short windows, retain safe geometry and scroll supporting content; later scan constraints may require layout review rather than an invented zoom destination.
- **Empty/error:** C13 insufficient/oversized or failed generation message replaces active QR, with edit/return path. No silent data truncation or automatic web-mode fallback. File/provider errors stay with retry; share return is not delivery success.
- **Large text:** Action labels stack and QR remains square. Never reduce supporting text to preserve QR above the fold.
- **Semantics:** The offline-sharing description and action purpose are readable. QR image has a short label pointing to the associated contact card, not raw encoded bytes read aloud.
- **P0.2 flows/components:** F04/F05/F06/F07/F11/F13/F15; C05/C06/C07/C13/C14/C15/C17/C18. Clarification A is unchanged; field mapping/limits/defaults remain P0.4.

## N03 — Profile

**Hierarchy:** Saved-profile summary, a prominent Edit Profile action, the Personalization and Data & Security groups, and a simple Delete Profile row at the bottom.

- **Top app bar:** C17 Profile title, no Up. Avoid decorative hero banners or extra profile-management menus.
- **Main content:** Saved profile image or neutral placeholder with name, professional title and organization when available. Edit Profile is prominent. Personalization contains Appearance and Visibility & Sharing; Data & Security contains Backup & Restore and Security & Encryption. Each row links to the existing settings and storage. Delete Profile is a simple settings-style row near the bottom, without a Danger Zone heading, warning panel or separate management screen.
- **Buttons/actions:** Edit Profile opens N04. Management rows are labeled actions with scope text and chevron; do not duplicate settings or add a profile selector. Delete Profile opens the standard “Delete Profile?” confirmation popup with Cancel and Delete Profile actions; confirming uses the existing local profile deletion workflow, preserves external backups, and returns to onboarding only after successful deletion.
- **Navigation:** C18 Profile selected. Rows open N04, N05, the draft-backed Visibility & Sharing route, N06, or draft-backed Security & Encryption. Back selects Share.
- **Spacing/alignment:** Group radius16dp, 16dp row padding, >=64dp row height with 24dp leading icon and flexible text. Decorative separators never serve as action boundaries alone.
- **Scrolling:** Body scrolls if text/display scale exceeds available height; avoid nested scrolling.
- **Empty/error:** If saved-profile state is unavailable, factual message and guided N04 route; no stale profile information or fake rows suggesting multiple profiles. Maintenance load error preserves caller with C13 retry.
- **Large text:** Supporting text wraps; chevrons remain separate from labels, rows grow. The Delete Profile row and confirmation popup actions remain accessible at 200% font scale. Nothing is clipped to one line to preserve a compact hub.
- **Semantics:** Each management row is one announced action with title and scope. Context label does not pretend to be an editable text field.
- **P0.2 flows/components:** F02/F08/F09/F10/F15; C11/C13/C17/C18. Keep the approved single-profile management model.

## N04 — Edit Profile (including guided first run)

**Hierarchy:** One reusable editor with Details, Contact and Advanced tabs; explicit Save Profile remains available while content scrolls.

- **Top app bar:** C17 Up and Edit Profile title. Save Profile is an explicit fixed-bottom action; first-run onboarding uses its own Welcome, Basic Information, Contact Information, and Review steps.
- **Main content:** Details contains identity, professional title/organization, biography and location. Contact contains phone, email, website and professional links. Phone entry pairs the number with a country/region selector and visible calling code; suggest the device's locale region without location access. Advanced links to draft-backed Visibility & Sharing, Security & Encryption, Hosted Profile, and Profile Images. Preserve every supported field, validation rule and independent visibility setting.
- **Buttons/actions:** Save Profile validates and commits the editor draft only on explicit action. Image selection uses E03 under Profile Images. Visibility changes stay in the profile draft until Save Profile succeeds. Contact Export has an independent default-on country-code formatting switch and a preview of the number that QR/.vcf will use; this does not change My Card visibility or whether the phone is exported. Security settings retain public-key import, validation, fingerprint and removal; Hosted Profile explains that its URL points to an existing public page and is not published or hosted by VCard Native.
- **Navigation:** No primary bar. Clean Up/Back returns to the actual caller; dirty exit opens D01. First-run Create My Card commits once and opens N02 Share; clean/confirmed-discard first-run exits. Nested Advanced routes return to the editor draft. Appearance image links and Share correction retain their established return behavior.
- **Spacing/alignment:** Sections separated24dp, fields16dp, supporting text4–8dp below relevant field. Independent controls go below their field on narrow/large-text layouts. Avoid dense two-column field/value forms.
- **Scrolling:** Tab content scrolls independently of the fixed Save Profile action; keyboard avoidance keeps focused fields and validation errors visible. At large font scale, tab choices stack vertically. Biography can grow without nested scrolling obscuring the enclosing form.
- **Empty/error:** Empty optional fields stay editable here with explicit labels; requiredness rules remain P0.4. C13 field errors retain draft, focus first failure and keep other input. Canceling selection preserves saved image; failed save retains unsaved work. No invented validation thresholds.
- **Large text:** Labels remain visible above values; switches stack; no clipped floating label or forced single-line section title. Buttons wrap/grow instead of overlapping Up/title.
- **Semantics:** Each field has persistent name, value, error/support association. C08 names include field plus card/export scope and checked state. Heading navigation supports long forms; selection icons don't create duplicate targets.
- **P0.2 flows/components:** F01/F02/F05/F11/F12/F13/F14/F15; C08/C09/C13/C14/C17/C20. Explicit Save and unsaved-change protection remain intact.

## N05 — Appearance

**Hierarchy:** Theme selection, accent selection, compact live card preview and explicit Save in a stable bottom action area. Preview depicts the one fixed design language; it is not a template gallery or a second editor.

- **Top app bar:** C17 Up, Appearance title and explicit Save. No primary navigation while editing secondary state.
- **Main content:** Noninteractive compact business-card preview of saved identity and available images, styled immediately with the selected Dark/Light theme and Sapphire/Jade/Amethyst accent. Do not place theme/accent labels or unsaved-state messages in the preview; controls already communicate the selection. C10 choices do not change the saved My Card appearance before Save. C11 Change profile/cover images leads to N04, never a local picker.
- **Buttons/actions:** Options use labeled check/selection and an opaque pair. Save Appearance stays in a stable bottom area, is enabled only when the draft differs from saved appearance, and explicitly commits the selection. Do not add a theme Auto option, color picker, font chooser, template or motion setting.
- **Navigation/draft branch:** Dirty Back shows “Discard appearance changes?” and “Your appearance changes haven't been saved.” Keep Editing preserves the preview; Discard Changes leaves without altering saved appearance. On dirty image-link request, show existing D01. Clean or explicitly saved choices permit the link using saved appearance. After ordinary Save returns N03, reopening N05 shows saved values. N04 return refreshes both saved appearance and imagery.
- **Spacing/alignment:** Options minimum48dp targets; swatch plus readable family label. Wrap option groups into a vertical list when needed, not tiny unlabeled circles. Preview uses same card radius/type roles but is visibly noninteractive.
- **Scrolling:** One body scroll; selection remains reachable while Save stays fixed above system insets. At large font scale, preview occupies less available space as needed; controls are never hidden to preserve artwork.
- **Empty/error:** Missing portrait/cover uses neutral fallback in preview. Failed save uses C13 and retains choices. Canceling N04 image selection cannot replace the existing saved image. No automatic appearance save.
- **Large text:** Option labels wrap and selected state remains visible; preview text wraps without clipping, and Save remains reachable at 200% font scale. Place image link after option groups in reading order.
- **Semantics:** Group theme/accent as single-choice sets with selected labels; preview is described once and is not announced as a functioning business card. Do not duplicate identity announcements unnecessarily.
- **P0.2 flows/components:** F08/F02/F12/F15; C01/C10/C11/C13/C17. Clarification B and the single N04 image-editing location remain binding.

## N06 — Backup & Restore

**Hierarchy:** Explain full-app backup versus .vcf, then Create backup and Restore backup groups, followed by operation-specific feedback.

- **Top app bar:** C17 Up, title Backup & Restore; no primary bar. Up follows caller (N03 or first-run N04), except approved temporary restriction during committed replacement.
- **Main content:** C12 action groups with short scope text: profile, images, appearance, visibility; hidden-from-sharing data is part of backup. Local-file destination support is clear; no cloud account/sync marketing. Restoration is visibly distinct from contact file sharing.
- **Buttons/actions:** Create full application backup is principal filled action; Restore application backup is a clearly labeled outlined/tonal peer. Opening a restore picker is not styled as an immediate destructive commit; only S02 confirmation replaces data. No merge, backup history, encryption claim, automatic pre-restore copy or undo.
- **Navigation:** File picker E01 returns to N06; validation happens before S02. S02 cancellation returns unchanged. Confirmed restore success refreshes all saved surfaces and opens N02 Share. Errors do not navigate to a new screen.
- **Spacing/alignment:** Two groups separated24dp, internal16dp, icons24dp, actions>=48dp. Replacement warning uses icon+body text rather than a wall of red.
- **Scrolling:** One body scroll. Progress remains within the affected group with status text, avoiding content shifts that misplace focus.
- **Empty/error:** No-profile entry still permits restoring a backup. Invalid/corrupt/unsupported input produces persistent C13 error and another-file/retry path; no S02 for failed validation. Write errors preserve local data. Unknown outcomes after interruption are not labeled success.
- **Large text:** Stack all buttons vertically; paragraphs wrap; progress explanation stays readable. The constrained committed stage does not hide why navigation is temporarily unavailable.
- **Semantics:** Action labels distinguish Create from Restore, scope from contact export, selected file from confirmed replacement. Announce validation/progress/result only when known. Backup metadata availability remains P0.4.
- **P0.2 flows/components:** F09/F10/F11/F12/F15; C12/C13/C14/C17/C19 (for S02). Safe commit/recovery and integrity mechanisms remain P0.4/P0.5 dependencies.

## S01 — Contact Export Preview

**Type:** Existing bottom sheet; no new full-screen destination. Use a raised C19 surface with 28dp top corners and the currently selected theme/accent. Keep the title Contact Preview and its concise description. Present the saved name prominently in a softly accented name panel, followed by only saved Contact Export-enabled values in spacious, labeled rows. Give rows category-appropriate decorative icons (identity, phone, email, web links, location, or biography) tinted from the selected accent; combine labels only when one exported URL represents multiple fields. Phone text uses the same saved country-code preference and formatted value as the contact QR/.vcf. Values remain read-only/selectable, wrap rather than truncate—including long phone, email, and URL values—and follow the app's typography and contrast tokens. The existing dismiss affordance retains a >=48dp target.

The sheet does not create or share a file. Actions remain Edit Sharing Settings and Done; dismissing never creates or shares an artifact. Both actions stay reachable at 200% text scale by scrolling the same sheet; long summaries and values do not clip or hide the controls.

Edit Sharing Settings dismisses S01 and opens N04 with Contact Export first and N02 as caller; the My Card category remains available below it. Saved changes require a fresh review before export. Snapshot change invalidates confirmation. Loading/error remains in this sheet/caller and keeps review data available without a false success. At large text expand the same sheet to available height and scroll all fields, retain action reachability, and return accessibility focus to the invoking N02 control on dismissal. F04/F06/F07/F13/F15; C07/C13/C14/C15/C19. QR display itself is not gated by S01.

## S02 — Restore Review

**Type:** Existing bottom sheet, only after successful backup validation. C19 raised shell, title Review restore, C12 replacement explanation and safe supported summary of what will be replaced. Do not invent schema/version/date fields as guaranteed metadata.

Use body text explaining replacement of local profile/images/appearance/visibility. Explicit filled/strong action Replace local data and restore (or Restore profile when none exists), with Cancel as a distinct non-destructive action. Destructive intent is conveyed in words plus error/icon treatment; contrast must remain readable. Confirm returns to progress in N06, not another dialog. Cancel/Back/swipe dismisses unchanged to N06.

Support long text/full-height expansion within the same sheet; actions wrap/stack. Announce title/warning without reading unknown file contents as verified metadata. Focus returns to restore control if cancelled. Invalid input never renders this surface. F10/F12/F15; C12/C13/C19. Technical validation/commit safety remains deferred and is not proved by this design.

## D01 — Unsaved Changes

**Type:** Single reusable dialog; C16. Raised opaque surface, 28dp corners, section-title typography, body text and two labeled actions. Keep editing is visually preferred; Discard changes uses clearly destructive wording and readable error color, without making red the only clue. No third Save-and-leave action.

Ordinary body: Your changes have not been saved. Keep editing or discard them? For a pending N05 image link, explain: Discard appearance changes and open Edit Profile using your saved appearance? Keep editing/dismiss returns to originating editor without navigation. Ordinary Discard returns/exits; pending image-link Discard restores saved appearance then opens N04. Never auto-save or display a second confirmation.

Width fits the viewport, max560dp with preferred24dp margins; height grows, body may scroll and actions stack for large text. Initial semantic focus reads title/body, action focus remains predictable, dismissal returns to the editor/invoking control. F01/F02/F08/F15; C13/C16. No extra destination is added.
