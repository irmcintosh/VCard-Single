## Common contracts

Use semantic color/type/spacing/shape roles, theme-paired foregrounds, at least 48dp actionable targets and content-driven height. Text/action meaning must survive large font/display scales, grayscale and dark/light appearance. Every interactive component has a visible focus state and labeled selected/checked/disabled state where relevant; no unsupported feature is exposed merely to demonstrate a component state.

Resting, focused and pressed states keep geometry stable. Required progress disables duplicate activation and includes status text. Known unavailable actions follow approved hide/disable/explanation rules rather than universal low opacity. Error/recovery/success messages are factual; an external handoff never proves delivery. Pressed/disabled compositing, actual rendering and assistive technology behavior remain untested. Rows/icons described below do not create new destinations or independently interactive artwork.

## C01 — Business card surface

**Purpose/visuals:** Opaque surface, 24dp corners, optional decorative subtle outline and restrained light shadow; groups cover/identity/actions without resembling management settings. Internal padding 20dp, major spacing 24dp. Background imagery never carries the sole readable identity text.

**States:** Saved profile, missing optional imagery/content, image load failure with neutral fallback; appearance draft preview in N05 is explicitly noninteractive. No selected-card or profile-switch state.

**Accessibility:** Read child headings/content in order; card itself is not an unlabeled button. Wrap name/bio and let height grow; don't shrink all contents to fit a card ratio.

**Reuse/requirement:** N01; noninteractive N05 preview. FR-01/FR-05; P0.2-01/P0.2-07.

## C02 — Profile header

**Purpose/visuals:** 3: 1 cover viewport, 88dp portrait/4dp surface ring, type.identity name, body title/organization; identity text below artwork on an opaque fill.

**States:** Cover/portrait present, absent or unreadable. No fabricated name/avatar data; use a neutral silhouette/shape. In short windows/large text, shorten decorative cover and place portrait in flow.

**Accessibility:** Name heading; portrait decorative when redundant. No duplicate spoken portrait/name group. Layout preserves long names and organization wrapping.

**Reuse/requirement:** N01 within C01; FR-01/FR-05, P0.2-11's conditional public-key row is separate and not implied by this header.

## C03 — Contact action

**Purpose/visuals:** Labeled native call, SMS, email or web action with 24dp icon, type.action and >=48dp target; tonal/outlined peers, clear spacing and wrap/stack behavior.

**States:** Available, pressed/focused, missing/hidden data (absent), missing-handler failure at caller with C13. Do not show disabled fake actions for absent optional content.

**Accessibility:** Purpose and relevant destination in accessible label; icon decorative beside text. Full label survives large text; browser/dialer/composer handoff is explicit without new confirmation.

**Reuse/requirement:** N01, F03; FR-01, P0.2-09. Does not initiate automatic calls/messages.

## C04 — Professional link / public-key action row

**Purpose/visuals:** Readable approved professional URL with leading icon, body label and external cue; optional public-key download variant uses explicit Download public key text. Use primary for actionable text, neutral supporting values.

**States:** Valid and display-enabled only; absent/invalid/hidden content omitted; focus/press; failed external/download action explained by C13. No arbitrary new link types or key formats selected here.

**Accessibility:** One action target per row; distinguish opening a URL from downloading the validated public key. Long URLs wrap without corrupting underlying data.

**Reuse/requirement:** N01, F03/F14; FR-01/FR-03, P0.2-09/P0.2-11. Input/format and exact integration remain P0.4/P0.5.

## C05 — QR display

**Purpose/visuals:** Black code on opaque white square with preserved encoder-defined quiet zone and additional 16dp white outer pad. Preferred panel 280dp, cap 320dp if room; no logo, colored modules or motion.

**States:** Immediate valid contact QR, valid web QR, generating (labeled C14; no stale active code), unavailable/error (C13 replaces code). Relevant saved changes invalidate earlier code/artifacts.

**Accessibility:** Concise QR label plus adjacent readable included data/URL; code pixels are not the only access to information. No universal scan support claimed. Don't silently shrink below later scan-safe geometry.

**Reuse/requirement:** N02, F04/F05/F07; FR-04, P0.2-05/P0.2-06. Limits/encoding remain P0.4.

## C06 — QR mode selector

**Purpose/visuals:** Two labeled options with primaryContainer/onPrimaryContainer selection, icon/check and text. Contact QR is default; web option is clearly online-dependent. Labels may wrap/stack, targets>=48dp.

**States:** Contact selected, web selected only when configured/valid, missing-URL explanatory state with N04 configuration link. No active fake QR/web export action.

**Accessibility:** Single-choice group/selected state, each mode's meaning announced; not color-only. Configuration guidance is not an additional destination.

**Reuse/requirement:** N02, F04/F05/F15; FR-04, P0.2-05. External return and fresh-entry mode rules are unchanged.

## C07 — Included-contact-data summary

**Purpose/visuals:** Readable supported included labels/values in body/supporting roles, no raw payload dump; contact mode presents it beside/below the immediate QR. Unsupported/omitted fields can be explained without disclosing export-hidden values.

**States:** Current saved snapshot, refresh needed, generation unavailable. Stale summary cannot justify exporting a different snapshot. No invented format mapping/defaults.

**Accessibility:** Logical label/value reading order, wrapping and headings where helpful; no essential values clipped or hidden in a tooltip. Review link has a real text label.

**Reuse/requirement:** N02 and S01/C15, F04/F06/F13; FR-03/FR-04, P0.2-06.

## C08 — Independent visibility-control row

**Purpose/visuals:** Supported field with separate Show on card and Include in contact export switches/checkboxes; controls stack below value at narrow widths. Use selected accents plus explicit labels, >=48dp targets and meaningful outline where needed.

**States:** Independently on/off, focused/pressed, support/essential-field restriction only when later rules establish it. No shared master switch or invented default.

**Accessibility:** Field name + scope + checked state for each control; no eye/share-icon-only labels. Long labels wrap; hosted-content independence help remains readable.

**Reuse/requirement:** N04, F13; FR-03, P0.2-04. P0.4 retains field support/default/non-hideable rules.

## C09 — Profile editor field

**Purpose/visuals:** Persistent label, input 16sp/24sp, neutral surface, 1dp meaningful outline, 2dp focus treatment, inline supporting/error text. Nominal 56dp input body grows; long biography uses a multiline area.

**States:** Empty, populated draft, focused, field error, save failure retained draft, save in progress. Required indicators only once actual requirements are specified. No example values saved silently.

**Accessibility:** Label/value/error association, focus first invalid field without deleting other entries; keyboard-visible scrolling and large text remain supported. Placeholder is never the sole label.

**Reuse/requirement:** N04 initial and later editing, F01/F02/F11/F14; FR-01/FR-02, P0.2-03/P0.2-04. Schema/validation deferred.

## C10 — Appearance option

**Purpose/visuals:** Labeled Dark/Light or curated accent choice with swatch, check and primary-container selection; whole option target>=48dp. Preview updates draft only.

**States:** Saved choice, unsaved preview selection, focus/press, save failure retained choice. No arbitrary color/font/template or automatic save state.

**Accessibility:** Single-choice group and selected label; color is supplemented by text/check; rows grow for large type. Preview is not a second live card/action surface.

**Reuse/requirement:** N05, F08; FR-05/FR-06, P0.2-07. Tokens here specify the approved fixed families.

## C11 — Management/navigation row

**Purpose/visuals:** >=64dp content-driven row, leading 24dp icon, clear title/support text and chevron only for actual navigation. Group fill/radius follows semantic tokens.

**States:** Rest/focus/press and unavailable destination explanation only when needed. N05 image-link activation may invoke existing D01; the row itself never autosaves or opens another image picker.

**Accessibility:** One combined action target with title/scope; decorative chevron ignored. Keep text readable and allow wrapping.

**Reuse/requirement:** N03's three entries; N05 image link; N04 first-run Restore backup link as text-row variant. FR-02/FR-05/FR-06, P0.2-02/P0.2-03/P0.2-07.

## C12 — Backup/restore action and replacement content

**Purpose/visuals:** Labeled action with explanatory full-app scope, icon and body text. Create backup/Restore backup on N06; explicit replacement action and warning in S02. Use no destructive styling on mere file selection.

**States:** Idle, destination/input selected, validating, validated review, committing, confirmed success or recoverable failure. Invalid input never reaches S02. No merge/history/undo control.

**Accessibility:** Label operation/scope; warn about replacement in words before action; show why navigation is temporarily unavailable during committed restore. Long warning/actions stack.

**Reuse/requirement:** N06/S02, F09/F10/F12; FR-06, P0.2-08. Data format, metadata and safe commit mechanism remain later work.

## C13 — Inline validation/status message

**Purpose/visuals:** Body/supporting message, meaningful icon and error/success/neutral semantic pair; recovery control when applicable. Errors remain in content, not solely a fleeting notice.

**States:** Validation error, missing handler, write/generation failure, confirmed local success, unknown outcome and configuration guidance. Never equate handoff return with delivery.

**Accessibility:** Associate field errors; announce status succinctly without repeated focus stealing; non-color status, wrapping and >=48dp retry target. Do not log/display unnecessary personal data as diagnostics.

**Reuse/requirement:** All N/S surfaces; F01–F15 where feedback occurs. FR-01/FR-02/FR-04/FR-06, P0.2-09/P0.2-12.

## C14 — Loading/progress indicator

**Purpose/visuals:** Restrained linear/circular native-style progress plus text on the caller's opaque surface. Use indeterminate state when real progress is unknown, never a fabricated percentage/countdown.

**States:** Loading saved data, generating, writing, validating or committed replacement; completion yields truthful C13. Prevent duplicate activation and remove stale QR as current.

**Accessibility:** Announce operation/state at sensible changes; no spinner-only information or flashing. Reduced motion still has an understandable static status; busy navigation follows P0.2.

**Reuse/requirement:** N02/N04/N05/N06/S01, F04/F06/F09–F12; reliability/offline gates, P0.2-08/P0.2-12.

## C15 — Export preview content

**Purpose/visuals:** C07 read-only values, action context, format-omission help and Edit export selections link inside S01/C19. Use explicit .vcf/Save contact QR/Share contact QR confirmation labels.

**States:** Voluntary QR review (Close, no export effect), required action preview, invalidated snapshot, generation failure/retry. No artifact generation before required confirmation.

**Accessibility:** Heading identifies preview/action; read-only rows don't claim editability; all actual included data and actions remain reachable at large text. Closing/dismissing does nothing destructive.

**Reuse/requirement:** S01, F04/F06/F07/F13; FR-03/FR-04, P0.2-06. Initial QR display is not blocked.

## C16 — Reusable unsaved-changes dialog

**Purpose/visuals:** D01 only: raised surface, section title, body and Keep editing/Discard changes. Keep editing preferred; Discard uses error-color text plus explicit label. Modal radius 28dp, max 560dp width, viewport-aware body/actions.

**States:** Ordinary dirty N04/N05 departure or pending N05 image link. Keep editing/dismiss stays at originating editor. Pending-link Discard restores saved appearance then opens N04; ordinary Discard returns/exits.

**Accessibility:** Announce title/context, stable focus order and invoker return, stacked actions at large text. No third action or new confirmation instance/type.

**Reuse/requirement:** D01, F01/F02/F08/F15; FR-02, P0.2-04/P0.2-07/P0.2-10.

## C17 — Top app bar and explicit-save action area

**Purpose/visuals:** Title 24sp/32sp, nominal 64dp plus top inset, >=48dp navigation/action targets. Roots show title; secondary screens show Up and explicit Save where applicable.

**States:** Normal, dirty-editor context, save busy/failure; restoration navigation restriction is explained, not hidden. If title/actions don't fit, height grows or Save uses the same screen's accessible lower action area.

**Accessibility:** Distinct Up/title/Save labels, no truncated essential title at large type; never intercept system Back to avoid dirty guards. Focused fields/actions stay visible with keyboard.

**Reuse/requirement:** N01–N06, F01/F02/F08/F15; P0.2-01/P0.2-04/P0.2-10.

## C18 — Three-item primary navigation

**Purpose/visuals:** My Card/Share/Profile always labeled, nominal 80dp plus bottom inset. Selected accent-container indicator and readable on-container foreground; inactive onSurfaceVariant. Stable equal target allocation with flexible height.

**States:** One selected root, focus/press; root reselection doesn't duplicate stack/reset data. Secondary screens have no primary bar. No badges, fourth tab or hidden label mode.

**Accessibility:** Selected item announced, icon decorative beside label, >=48dp targets, enlarged text wraps without changing destination names/order.

**Reuse/requirement:** N01–N03, F15; P0.2-01/P0.2-02/P0.2-10. Back/root contracts stay approved.

## C19 — Bottom-sheet shell

**Purpose/visuals:** Existing S01/S02 only: raised opaque fill, 28dp top corners, decorative handle, title, labeled dismiss route, scrollable body and content-driven action region. Max 600dp width; full-height expansion is still the same sheet.

**States:** Review, action-specific context, busy/error as allowed; Back/swipe/cancel has the existing no-export/no-replacement effect before commit. No new modal destination.

**Accessibility:** Title/content focus, orderly scroll and label/value reading, controls never obscured by insets; action area stacks at large type. Dismissal returns focus to invoker.

**Reuse/requirement:** S01(C15) and S02(C12), F06/F07/F10/F15; P0.2-02/P0.2-06/P0.2-08.

## C20 — Image-selection row

**Purpose/visuals:** N04-only profile/cover field row with current thumbnail/fallback, clear image role and labeled selection action; thumbnail is not a second tiny target. Changes remain editor drafts until Save.

**States:** Existing saved image, absent image, selected draft, picker cancelled, load/input failure. Cancel never replaces saved imagery; no crop/filter feature or local image editor added.

**Accessibility:** One target with image purpose, selection state and error/support association; thumbnail decorative when redundant. Grow row for long labels/large type.

**Reuse/requirement:** N04, F01/F02/F08; FR-01/FR-02, P0.2-04/P0.2-07. N05 uses C11 to enter N04 instead of this component.

## Component scope review

Each component above has an approved feature/flow use and an appearance/state/accessibility contract. C19 is a reused shell, not a third sheet; C16 is existing D01, not another dialog. C01's N05 preview has no new actions. No account, multiple-profile, Wallet, NFC, sync, payment or advanced customization component is introduced. Component references were checked as documentation only; no runtime library, sample app or Android resources are created. P0.3 owner approval is recorded after successful guideline reconciliation; approval does not mean these components are implemented or tested.
