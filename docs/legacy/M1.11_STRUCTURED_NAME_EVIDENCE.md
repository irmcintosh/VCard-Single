# Milestone 1.11 Step 4E - structured names

Date: 2026-11-01. Status: implemented and automated-verified; **Milestone 1.11 OPEN**, updated-APK physical recipient tests pending. Milestone 1.12 not started.

## Contract and compatibility

- Required Full Name stays the saved card identity and vCard FN. Optional First/Middle/Last Name are entered manually; there is no splitting, transliteration, component guessing or Full Name rewriting.
- Apply existing single-line NFC, whitespace trimming, Unicode/control validation and 160-scalar per-name limits. Empty editor fields normalize to absent values, not saved empty strings.
- AppData schema 3 adds firstName/middleName/lastName under A2 profile.fields and as flat backup profile properties. Corresponding visibility entries have showOnCard=null and independent includeInContactExport booleans, default false. Full Name alone remains valid.
- Strict schema-1/2 codecs keep their exact older key sets and add in-memory absent name values/export-off preferences. Read does not rewrite an older live generation. The next explicit save/restore or new backup uses schema 3. Schema-3 keys and types remain strict; a malformed current profile is not silently treated as legacy.
- Existing phone display/region/E.164/export preference, identity, images, key, appearance, timestamps and privacy are preserved. Backup ZIP formatVersion 1, entries, limits, inventory, and A2 manifest/pointer framing are unchanged. No operation-intent state transition changes. Older APKs reject schema 3/new backups; no downgrade safety.
- With at least one present, export-enabled name component: VERSION:3.0, **N before FN**, with Last/First/Middle/empty Prefix/empty Suffix. Escape each component before adding exactly four separating semicolons. Excluded components are empty.
- With no included name components: byte-identical legacy FN then N:;;;;. Empty N has observed iPhone Camera identity limitations; manually enter and enable components instead of inventing a surname.
- Contact Preview retains Full Name first, followed by individually labeled included First/Middle/Last values. All contact rows, QR and native VCF use the one saved privacy-filtered ContactExport.
- No changes to valid NOTE escaping, country-code formatting, URLs, phone validation, FileProvider lifetimes, QR encoder, resource/capacity/geometry protections, dependencies, networking or hosting.

The owner reports successful Candidate 01 Android/iPhone native QR structured-name tests and correct direct VCF structured-name import. The owner also reports direct Android VCF/iPhone imports interpret escaped NOTE newlines; Android Camera can display literal `\n`. These are owner observations, not automated proof or universal recipient certification.
