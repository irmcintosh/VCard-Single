## 2. Derivation method

The icon was not redrawn or redesigned. Every Android raster was rendered directly from the approved SVG markup with headless Google Chrome, which was already installed. Inkscape is installed but fails to start (`0xC0000139`), so it was not used. Each target size was rendered from vector rather than resized from another raster.

Variants were derived only by removing whole groups or adding a placement transform. Shapes, gradients, colors and proportions are unchanged.

| Variant | Derivation from approved SVG |
|---|---|
| Adaptive foreground | Master with `rect#canvas` and `g#frame` removed. The V, back card, front card and contact group were rescaled uniformly (1.6010 px per board unit at 1024) and centered on the opaque content bounds. |
| Adaptive monochrome | Monochrome SVG wrapped in a uniform placement transform so it overlays the foreground exactly. |
| Legacy square `ic_launcher.png` | Master with only `rect#canvas` removed. This keeps the approved glowing rounded-square frame on a transparent surround. |
| Legacy round `ic_launcher_round.png` | **Final (owner decision):** frameless circular icon — adaptive background plus foreground, cropped to the visible 72 dp viewport and clipped to a circle. The glowing frame is kept in the main `ic_launcher.png` and the approved SVG masters. |
| Adaptive background | Vector drawable reproducing the master's `panelFill` radial gradient (`#0B3C8C` → `#05175A` → `#0A0636`, center 25%/20%, radius 0.95), full-bleed. |

The generator is a session-side helper script, not part of the project. Derived intermediate SVGs were kept only in the agent session workspace.

## 4. Adaptive masking

- **Safe zone:** measured on the 1024 px foreground render, the farthest opaque pixel (alpha ≥ 50%) is 32.15 dp from the center. This is inside the 33 dp radius of the 66 dp safe-zone circle. The soft drop shadow reaches 33.89 dp, which is still inside the 36 dp visible viewport.
- **Mask behavior:** no V, card or contact detail is clipped by circle, squircle, rounded-square or teardrop masks.
- **Glowing frame:**
  - It is preserved in the main legacy `ic_launcher.png` icons and in the approved SVG masters.
  - It is omitted from the adaptive layers, so the launcher mask does not produce a second rounded-square border inside the system shape.
  - By owner decision, it is also omitted from the legacy round icons, which are frameless circles. This avoids `IconLauncherShape` lint warnings and frame corners cut by a circle.
  - In adaptive form, the frame's role is filled by the approved deep-navy panel gradient as the full-bleed background.
- **Monochrome placement:** the monochrome layer reaches 31.96 dp and uses the same placement as the foreground.

## 5. Monochrome (themed icon) implementation

`mipmap-*/ic_launcher_monochrome.png` is rendered from the approved monochrome SVG:

- White on transparent, with no gradients, glows or shadows.
- Referenced by `<monochrome>` in both adaptive XMLs.

Android 13+ launchers use this layer when themed icons are enabled. API 31–32 ignore it.

## 6. Legacy fallback scope

`minSdk` is 31. The `mipmap-anydpi` adaptive definitions (packaged as `mipmap-anydpi-v21`) therefore take precedence on every supported device. The density PNGs `ic_launcher.png` and `ic_launcher_round.png` are retained as conventional fallbacks for tools and stores that read raster icons. No supported launcher is expected to display them.

## 9. Outstanding issues and limitations

- The artwork is a vector reconstruction approved in Step 3B. It is not the original designer source.
- The adaptive icon and, by owner decision, the legacy round icons omit the glowing frame. The main legacy `ic_launcher.png` and the approved SVG masters preserve it.
- Themed-icon, API 31 and physical-device launcher rendering are unverified.
- The unsigned release APK is not distributable. Production signing remains isolated and unchanged.
- The Android 12+ system splash screen derives its icon from the adaptive launcher icon, so it will now show the new icon automatically. Splash configuration is unchanged.
- The API 37 AVD now has the debug build installed instead of the test-signed release build. Reinstall the release build if it is needed for later release tests.
- Pre-existing known issues are carried forward unchanged:
  - Android Camera QR Notes newline display.
  - Older APKs cannot read schema-3 profiles.
  - Physical structured-name recipient testing is incomplete.
  - M1.12 accepted residual risks.
