## 1. Current professional-link architecture

**Data and persistence**
- Links are stored as a list of `SocialProfile` entries in `Profile.kt`. Each has an id, platform, label, URL, a show-on-card setting, an include-in-contact-export setting and a legacy field.
- Order is simply list order; `moveSocialProfile` reorders them.
- The old LinkedIn, GitHub and "Other professional link" fields are still migrated and mirrored into this list.
- `ProfileCodec.kt` saves the list as `socialProfiles`, and `BackupDataCodec.kt` carries it in backups.
- There is **no limit on the number of links**, and duplicate entries are allowed.

**Platforms**
- `SocialPlatformOption` has these stored IDs: `linkedin`, `github`, `facebook`, `instagram`, `x`, `youtube`, `tiktok`, `threads`, `bluesky`, `mastodon`. There is also `Other`, which stores a custom name.
- `SocialPlatformSelection.fromSaved` matches stored values ignoring case, accepts display names, and maps `twitter` to X. Anything else becomes Other, including the legacy `otherProfessional`.

**Validation and editing**
- `socialProfileFieldErrors` requires:
  - a platform and a label, each up to 160 characters;
  - an HTTPS URL of up to 2048 characters.
- `browserUrlCandidate` normalizes URLs.
- Editing happens in `SocialProfileEditor` in `ProfileScreens.kt`. It's backed by the add, edit, remove, select-platform and move functions in `ProfileViewModel`.

**Data flow to the card**
- `toMyCard` turns each saved entry into a `CardProfessionalLink` (label, URL, platform).
- `visibleProfessionalLinks` drops links that have a blank label, are hidden from the card, or have an invalid URL. Order and duplicates are preserved.

**Rendering**
- `ProfileCard` is the single renderer for both My Card and the Appearance Editor's live preview. The gallery thumbnails are separate static drawings and are not affected.
- **Classic renders its links itself**, in a private `ProfessionalLinks` in `ClassicCard.kt`.
  - It's a horizontally scrolling row of 48 dp cells.
  - LinkedIn and GitHub show an icon only; every other platform shows its label as underlined text.
  - There is no visible label under the icons.
- **The other six styles share one component:** `ProfessionalLinkList`.
  - It's a vertical list of rows, each an icon plus text.
  - Icons come from `professionalLinkIcon`. That mapping only recognises lowercase `linkedin` and `github`; everything else gets the generic external-link icon.
  - Each style calls it with its own options:

| Style | How links are placed today |
|---|---|
| Minimal | Plain list |
| Professional | Compact list with dividers, inside `ProfessionalPanel` |
| Modern | Section label plus list |
| Executive | Divider, muted label, compact list |
| Editorial | List with dividers, inside `EditorialSection` |
| Horizon | Section label plus list |

**Tap behaviour**
- Every link sends a "Social" action with the link's URL to `openContactAction`.
- That re-checks the URL as HTTPS and opens it in a browser. It shows a toast if the URL fails or no app can open it.
- This matches the legacy architecture's rule: open HTTPS links with `ACTION_VIEW` and handle the case where no app is available.
- Each link's screen-reader text is the existing string `social_open_description`: "Open %1$s: %2$s".

**Custom Share, Hosted Profile and widget**
- None of these use social links.
- Links only leave the app through the vCard (`ContactExport`), for entries marked for contact export. This milestone doesn't touch that.
- Modern's contact tiles don't include social links. The tile mapping has a branch for them, but it is never reached.

## 5. Recommended shared design

**New file `SocialIconGrid.kt`** in `ui/screens/card/`, next to the existing card components rather than the legacy `ui/components/` suggestion. It would contain:
- **`socialPlatformIcon(platform)`:** a pure function built on `SocialPlatformSelection.fromSaved`, so the card recognises the same names as the editor. It returns one of the 10 brand icons or the Other icon.
- **`socialGridColumns(widthDp, fontScale, count)`:** a pure function that computes columns from a minimum cell width that grows with font scale, giving 1 to 4 columns.
  - It follows the balanced-row approach Modern already uses, which avoids experimental Compose APIs.
- **The `SocialIconGrid` composable:** rows of equal-width cells, each at least 48 dp. Each cell shows an icon (about 24 dp) above a visible label, limited to 2 lines with an ellipsis.
  - The screen-reader text stays "Open label: url".
  - Cells are keyed by position so duplicate links survive.
  - Tapping sends the same Social action with the same URL, so opening behaviour is unchanged.
  - It takes small presentation options (compact, muted, container colour) for each style.

**Changes to `CardSections.kt`**
- `ProfessionalLinkList` keeps its name and signature but draws the grid.
- `professionalLinkIcon` uses the new mapping.
- The six style files need little or no change, and the existing test that each style calls `ProfessionalLinkList(content` keeps passing.

**Colour:** single-colour icons tinted with the accent on a tonal surface.
- They follow the light/dark theme and the accent, and fit the guideline's "restrained accent".
- Bundled vector drawables work offline, as the architecture requires.
- This depends on the licensing decision below.

## 7. Risks and licensing

- **Licensing (main risk):** the logos are trademarks of their owners:
  - Meta (Facebook, Instagram and Threads)
  - Google (YouTube)
  - X Corp
  - ByteDance (TikTok)
  - Bluesky
  - Mastodon gGmbH
  - Microsoft (LinkedIn)
  - GitHub

  Even freely licensed icon artwork doesn't grant trademark rights. Some brand guidelines also restrict recolouring, so tinting with the accent may not be allowed for every brand. The UI guidelines already require identity imagery to be supplied or authorised by you. So you'll need to supply or approve the artwork and how it's coloured, and we should record where each icon came from. This isn't legal advice. I downloaded nothing.
- **Layout:** labels can be up to 160 characters, there's no limit on link count, and large font scales could make cells very tall.
  - The 2-line ellipsis, with the full text available to screen readers, handles this.
  - It still needs emulator checks at narrow widths and at 1.5x or larger fonts, as both the shared rules and the legacy guidelines require.
- **Look:** in Modern the grid could resemble the contact tiles, and in Executive and Editorial it could make the card feel more crowded.
- **Recognition differences:** today the card recognises only lowercase `linkedin` and `github`. With the new mapping, saved values such as "LinkedIn" or "twitter" will also show a brand icon. The saved data itself doesn't change.
- **Data:** saved data, schema 5 and backups are not affected, and no new dependencies are needed.
