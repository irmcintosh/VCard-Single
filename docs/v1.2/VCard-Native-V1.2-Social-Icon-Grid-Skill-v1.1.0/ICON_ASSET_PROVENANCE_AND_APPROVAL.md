# Original Social Symbols — Design Provenance and Approval Gate v1.1.0

**Design direction APPROVED; application asset integration NOT YET AUTHORIZED.** The owner explicitly rejected a workflow requiring official brand-kit downloads and approved the custom black/white icon mockup with `in` for LinkedIn and `f` for Facebook. The previous official-logo acquisition gate in v1.0.0 is superseded for the new six-style grid.

## Required record for every new symbol
Platform ID, intended generic symbol from `APPROVED_ICON_DESIGN.md`, implementation file or Compose function, whether drawn from scratch or reused, any external code/artwork source and license, SHA-256 of generated asset if applicable, review date, visual similarity assessment, and owner approval status. Do not invent copyright/license claims or present self-created artwork as an official platform logo.

## Artwork policy
- Prefer simple original generic symbols and plain typographic glyphs, not tracing or close copies of protected platform logos.
- Specifically: LinkedIn `in` (plain text), Facebook `f` (plain text), GitHub code, Instagram camera, YouTube play, TikTok note, X chat bubble, Threads @, Bluesky overlapping bubbles, Mastodon chat bubble, Other chain link.
- Platform labels are plain text identifying destinations; retain the actual saved label and accessibility URL.
- Generic symbols can use theme-appropriate monochrome/accent treatment after accessibility contrast review. The approved reference shows white on black; it does not mandate one background for every style.
- `in` and `f` are strongly associated with their platforms. Original drawing does not remove all trademark/trade-dress risk. Compare final rendering to official brand marks and stop if too close; seek further owner decision when uncertain.
- The prior staging directory of official Bluesky/Mastodon SVGs is **not** an approved input for this custom icon grid. Do not import it.
- Existing `ic_linkedin` and `ic_github` in Classic have unknown provenance and are tinted; Classic is explicitly frozen. Document this separate legacy concern for pre-release review, without changing Classic.

## Gate to implementation
Owner must separately authorize code/resource changes and any project documentation additions. Final icon visuals must match approved mockup. No automatic assertion of legal clearance; consider specialist review if publishing a commercial product raises unresolved concerns.
