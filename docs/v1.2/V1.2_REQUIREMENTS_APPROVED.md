# VCard Native V1.2 — Approved Requirements Baseline

**Status:** Requirements approved by project owner, 2026-11-04. **Implementation NOT authorized.**
**Document purpose:** Record the approved V1.2 feature scope; supplements, and does not overwrite, V1.0/V1.1 records.
**Baseline:** V1.1 application `com.mackseoul.vcardnative`; preserve user data, signing continuity, existing functions, and approved architecture.

## 1. Release scope

V1.2 comprises (a) Card Personalization, (b) QR Image Export, (c) Social Presentation, and (d) Quick Card Widget and Custom Share polish. These are requirements, not evidence of implementation or testing.

## 2. Card Personalization

### Seven styles

1. **Classic:** Preserve the current V1.1 My Card design established by owner-provided device screenshots.
2. **Minimal:** Display Full Name plus up to **four** user-selected additional items. Full Name is mandatory and excluded from the limit.
3. **Professional:** Structured business-focused composition, organized contact panel, refined accent treatment.
4. **Modern:** Contemporary visual hierarchy, expressive accents, contact-action tiles.
5. **Executive:** Premium, elegant typography and restrained styling.
6. **Editorial:** Magazine-inspired composition and typography-led hierarchy.
7. **Horizon:** Immersive cover and layered presentation; final design must remain distinct from Modern.

**Compact is explicitly removed without replacement.** All styles except Minimal preserve the same existing eligible profile information and actions. No style may delete profile data, alter sharing payloads, or remove screen-level navigation. Respect saved cover images and portraits.

### Minimal-specific requirements

- The additional selectable items are: Profile Photo, Cover Image, Professional Title, Organization, Biography, Phone, Email, Location, Website, Professional Links, and Hosted Profile Link/QR.
- Allow zero to four selected items, with a visible `n / 4` counter; prevent a fifth selection until another is deselected.
- Professional Links counts as **one section**, regardless of how many saved links it contains.
- Hidden items remain in the saved profile; selections persist independently and survive switching styles.
- Existing My Card navigation, sharing and profile-editing access remain available.
- **Proposed detail pending confirmation:** A selected item with no saved value remains selected but produces no empty card row, and the editor indicates the missing value.

### Accent palette and theme

- Exactly six accents: preserve V1.1 **Sapphire, Jade, Amethyst** identifiers and source-defined color mappings unchanged; add **Warm Gold, Coral, Silver**.
- Proposed new hex values: Warm Gold `#E4BD75`, Coral `#F28F85`, Silver `#BBC6D4`. These exact values require contrast/design verification before finalization.
- Existing accent hex values and original theme/accent defaults **must be verified from current V1.1 source**, not illustrative swatches.
- Light/dark application theme, card style and accent are independent choices; no arbitrary custom color picker.
- The Quick Card Widget synchronizes **saved accent only**, not selected card style.

### Appearance Editor

- Vertically scrollable combined editor: theme, accent, seven-thumbnail **visual gallery**, and larger live preview **below** the gallery.
- Thumbnails must depict genuinely distinct styles. Larger preview must use the same rendering system as My Card and the saved profile with draft appearance choices.
- **Save** persists appearance settings (including Minimal selections as applicable); **Cancel** discards draft changes; **Restore Default** resets theme, accent and style to verified original defaults in the **draft only**, requiring Save to persist.
- Preserve unsaved-changes confirmation; no uncommitted editor data may leak into saved card, sharing, or widget.
- Support long values, narrow screens, accessible contrast, labels, touch targets, and font scaling.

## 3. QR Image Export

- Add **Save Image** and **Share Image** to each of: Primary Contact QR, Custom Share QR, and Hosted Profile QR.
- Produce a single automatically sized, high-quality, scannable PNG with appropriate quiet zone; preserve each context's **existing exact encoded payload**.
- Save via Android MediaStore to `Pictures/VCard Native`, using unique timestamped, collision-safe names; never overwrite an earlier image.
- Share PNG independently through Android Sharesheet using temporary narrowly scoped URI access; no broad storage permission.
- Confirm only successful saves; report failures accurately. Preserve current QR presentation, vCard export, and sharing actions.
- Acceptance: saved/shared PNGs from all three contexts scan to the same data as their original QR screens.

## 4. Social Presentation

- On **My Card only**, present configured links as a responsive, labeled icon grid.
- Dedicated recognizable icons for LinkedIn, GitHub, Facebook, Instagram, X, YouTube, TikTok, Threads, Bluesky, Mastodon; generic icon for Other.
- Preserve URLs, existing order, duplicates, validation, and link-opening behavior. Maintain accessible targets and font scaling.
- No changes to Hosted Profile URL editing/QR, external hosted websites, widget links, or Custom Share fields. Review platform icon asset licensing before implementation.

## 5. Quick Card Widget Polish

- Preserve compact/standard/expanded RemoteViews layouts, existing name/title/photo/initials content, existing widget instances, body-tap Share action and overflow My Card/Share/Profile actions.
- Improve spacing, alignment, hierarchy, long-text handling, and saved-accent synchronization after successful appearance Save.
- **Do not add Organization or any other widget profile fields.** Do not apply card styles or introduce new widget controls.

## 6. Custom Share Polish

- Preserve automatic Full Name and exactly four optional fields: Professional Title, Organization, Phone, Email.
- Improve selection/review visual clarity and feedback without changing confirmed selection persistence, QR/vCard payload generation, or Android Sharesheet behavior.
- Live preview must show the **actual exported field values** derived from the existing contact export model, including the exported phone formatting, rather than raw saved phone text when they differ.
- Preview updates with selection changes; unavailable values are handled clearly without fabrication.
- Acceptance: displayed values correspond to exported contact information, with no additional data exposed.

## 7. Cross-cutting safeguards and acceptance

- Preserve application ID, V1.1 profiles/photos/cover images, existing backup compatibility, release signer, current contact/QR/share behavior, and widget instances.
- Source audit reported current profile schema **4**. Schema 5 is only a technical **proposal**, not approved. Any migration requires separately approved design and verified backward compatibility.
- Do not change protected Gradle/SDK/JDK/Manifest/signing settings without specific approval. Follow `VCARD_NATIVE_ANDROID_STUDIO_PROTECTION_SKILL.md` and verified external backups before any later code changes.
- Required future checks: unit/regression tests; QR scan tests for three contexts; accessibility; widget launcher/device checks; in-place V1.1→V1.2 upgrade with preserved data; signing continuity; physical-device validation.

## 8. Scope exclusions

Cloud sync/accounts; Google Wallet; external Hosted Profile site changes; new social platform types; custom color picker; new widget fields/controls; new Custom Share fields; changes to QR payloads; broad storage permissions; wholesale architecture replacement.

## 9. Approval boundary

**Approved:** The requirements scope in this document, including seven styles and Minimal's four-item limit.
**Not approved:** Kotlin/Compose implementation, schema migration, dependency changes, project configuration changes, release, or testing claims. Technical details identified as pending require verification and, where applicable, separate owner decisions.
