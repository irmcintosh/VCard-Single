| V11-02 | Quick Share uses existing single phone and single email fields; no multi-entry expansion. |
| V11-03 | Quick Share excludes social profiles from selections, QR, and vCard only. |
| V11-04 | All 13 approved website/social design decisions remain in V1.1. |
| V11-05 | Quick Share selection state is independent of existing export visibility settings; confirmed share selections persist, cancellations do not. |
| V11-06 | Launcher shortcut opens primary QR; shortcut Back/Close exits to home, in-app navigation remains unchanged. |
| V11-07 | Generated Full Name follows First → Middle → Last; preserve legacy name unless structured name intentionally changes. |
| V11-08 | Social-profile data evolution must preserve legacy LinkedIn, GitHub, and Other Professional Link values. |
| V11-09 | Quick Card Widget is responsive for 2×1, 2×2, and 4×2 targets, subject to launcher verification. |
| V11-10 | V1.1.f technical feasibility, V1.1.g design, and V1.1.h requirements approved at planning level. |
| V11-11 | Historical V1.0.0 docs remain available; V1.1.0 becomes the active development focus. |
| V11-12 | Quick Share has an independent selection state. Existing `includeInContactExport` settings neither filter nor change Quick Share; primary QR and ordinary exports retain existing behavior. |
| V11-13 | Original Quick Share allowlist was FullName, ProfessionalTitle, Organization, Phone, Email, and Website (`ProfileField` identifiers verified in the V1.0.0 source). V11-17 supersedes FullName's selectable/optional treatment; the remaining five fields are selectable. No social or application-only data is included. |
| V11-14 | Name components allow 200 Unicode code points each; generated Full Name allows 602 including at most two separator spaces. This supersedes the V1.0.0 160-code-point limit only for affected names; no silent truncation or unrelated-field limit changes. |
| V11-15 | Newly entered website/social URL text is stored exactly as entered, without validation, normalization, rewriting, or HTTPS insertion. Existing saved URL text is preserved. Android link opening must use a separate safe URI boundary and never mutate stored text. This V1.1 rule supersedes conflicting V1.0 URL-normalization requirements. |
| V11-16 | Migrate the current LinkedIn, GitHub, and Other Professional Link slots additively into an ordered, repeatable social-profile collection. Preserve values, export visibility, and URL text; migrate in LinkedIn → GitHub → Other Professional Link order; support repeated platforms/URLs, unknown platform names, backup/restore, and idempotent migration. Require upgrade compatibility; do not promise downgrade compatibility. |
| V11-17 | Quick Share automatically includes the saved Full Name in every contact; it is not selectable. The five selectable additional fields are ProfessionalTitle, Organization, Phone, Email, and Website. Require at least one populated additional field to continue; Select All/Clear All apply only to those five. Full Name plus the same confirmed additional-field selection is used for QR and vCard. Save only confirmed additional selections when sharing is initiated; preserve independence from export visibility. If saved Full Name is unavailable, do not fabricate identity and require attention. This decision supersedes the earlier optional/selectable Full Name requirement and V11-13's original six-selectable-field interpretation. |
| V11-18 | For Quick Share V1.1.0, Website is excluded from selection, confirmed-selection persistence, filtered vCard, and QR. The selectable additional allowlist is exactly ProfessionalTitle, Organization, Phone, and Email. This supersedes the earlier five-field additional allowlist in V11-13/V11-17; V11-17's automatic, nonselectable saved Full Name rule remains in force. Ordinary Website profile behavior and ordinary contact export are unchanged; V1.1 exact URL preservation remains applicable there. |
| V11-19 | 2026-11-04: **Custom Share** is the approved user-facing name for the selective sharing flow. Existing `QuickShare` Kotlin identifiers and storage keys may remain internal; their presence does not change the UI terminology or V11-18 field allowlist. |
| V11-20 | 2026-11-04: Remove the redundant **Show QR** control from My Card. The primary Contact QR remains reachable through the Share destination and the **Show My QR Code** launcher shortcut. The separate Hosted Profile QR remains separate. |
| V11-21 | 2026-11-04: Accept the decorative QR-with-V vector icon for the single static **Show My QR Code** launcher shortcut. The shortcut opens the primary Contact QR. A warm shortcut request from any dirty editor route must use the existing discard confirmation; Keep editing preserves the current route/draft, while Discard proceeds using saved profile data. Owner-reported targeted emulator regression: 5/5 checks passed. |
| V11-22 | 2026-11-04: Accept the Quick Card widget's implemented responsive compact, standard, and expanded layouts and native launcher-managed move/resize/remove behavior. Body tap opens Share. The three-dot menu offers My Card, Share, and Profile. Content uses saved profile values and visibility; committed profile changes request refresh. This supersedes the earlier body-tap-to-My-Card wording in the planning requirements; no new widget destination or alternate navigation model is introduced. |
| V11-23 | 2026-11-04: Record V1.1 implementation complete for approved scope and feature acceptance complete for the tested scope; the targeted dirty-draft correction is owner-accepted. Latest reported JVM suite: 287/287 tests passed across 37 suites; debug assembly and Android-test compilation passed; lint reported 0 errors and 69 warnings at the regression-audit checkpoint. Android instrumentation execution remains NOT RUN because no device was connected. Release-readiness assessment, release signing, physical-device verification, and release/deployment approval remain outstanding; this entry does not authorize release or V1.2 work. |
