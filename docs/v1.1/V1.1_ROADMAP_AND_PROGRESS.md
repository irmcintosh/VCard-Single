## Development progress

### Custom Share (1.1.a)

- **Implemented and manually accepted.** **Custom Share** is the user-facing name; established `QuickShare` Kotlin identifiers and persistence keys remain internal.
- Saved Full Name is automatically included. The only selectable additional fields are Professional Title, Organization, Phone, and Email. Website and social profiles are excluded. Its saved selections are independent of ordinary export visibility and change only when sharing is initiated.
- The redundant My Card **Show QR** action is removed. Primary Contact QR remains available from Share and the Show My QR Code launcher shortcut.
- Current regression verification is summarized below. Owner emulator acceptance and automated JVM results are distinct from instrumentation execution, which remains outstanding.

### Long-Press QR Shortcut (1.1.b)

- **Implemented and owner-manually accepted:** the static **Show My QR Code** shortcut uses the accepted decorative QR-with-V vector icon and opens the primary Contact QR. Cold/warm intent routing is implemented.
- **Dirty-draft correction:** shortcut navigation from a dirty editor or nested editor now uses the existing discard confirmation. The owner reported **5/5 targeted emulator regression checks passed**. The resulting QR uses saved data; Keep editing preserves the current draft and route.
- Automated instrumentation execution remains outstanding. The earlier runner attempt stopped before executing tests; the latest `:app:connectedDebugAndroidTest` attempt reported `DeviceException: No connected devices!`.

### Automatic Full-Name Generation (1.1.c)

- **Implemented:** read-only selectable preview, First → Middle → Last generation, approved 200/602 code-point limits, save-only commit, structured-name export rules, and legacy-name preservation are present.
- The outdated setup instrumentation expectations were updated to assert FirstName validation and generated Full Name. Instrumentation sources compile; automated instrumentation execution is not claimed.

### Professional Website, Social Links & Hosted Profile (1.1.d)

**Feature status: IMPLEMENTED AND OWNER-ACCEPTED (2026-11-03).** This is feature-level acceptance, not V1.1.0 release approval. The stage-specific counts below are historical checkpoints; the latest V1.1-wide regression result is recorded in the current verification section.

**Stage 1 — Schema-4 data foundation: COMPLETE.**

- Ordered, repeatable social entries with stable IDs, platform, editable label, exact URL, Show on Card and Include in Contact Export controls; duplicate platforms and URLs supported.
- Legacy LinkedIn/GitHub/Other Professional Link migration and compatibility projections; profile and backup codec support; ordered contact export; Quick Share isolation.
- URL rules: Website HTTP/HTTPS; social and Hosted Profile HTTPS only; preserve exact entered URL strings.
- Resolved whitespace-only legacy-link handling, schema-4 JSON test fixtures, and legacy-visibility normalization affecting repository manifest round-trip saves. Focused tests and full unit suites passed after corrections.

**Stage 2 — Native Website, Social Links and Hosted Profile UI: COMPLETE; OWNER-ACCEPTED.**

- Contact editor provides Website and repeatable social links with Add/Remove, Move Up/Down, visibility/export switches and editable labels. Platform uses an 11-option Material 3 exposed dropdown, with Other custom platform entry; known selections auto-populate the label without overwriting user-customized labels. Saved URLs, entry order and duplicates remain intact.
- My Card displays Visit Website, ordered LinkedIn/GitHub monochrome icons and labeled unsupported-platform links, plus View My Online Card. Links open externally, not in a WebView.
- Hosted Profile URL editing was restored to **Edit Profile → Advanced → Hosted Profile**, removed from Contact; saved value drives My Card. Save/discard and draft behavior retained.
- Owner manually tested social editing, saving and My Card link behavior; reviewed and accepted the corrected dropdown and Advanced layout. Material 3 1.3.2-compatible `MenuAnchorType` resolved a temporary compilation issue. At the last Stage 2 checkpoint, **256/256 tests and debug assembly passed**.

**Stage 3 — Separate Hosted Profile QR: COMPLETE; OWNER-ACCEPTED.**

- A compact, independently tappable **48dp QR icon** appears alongside **View My Online Card** in the same My Card row, without an extra row.
- Dedicated **Online Card QR** screen reuses the existing QR encoder/rendering infrastructure and displays a high-contrast QR, saved URL, and Back/Done navigation to My Card.
- QR payload is **only the exact saved HTTPS Hosted Profile URL**, never contact/vCard content or unsaved draft data. Existing Contact QR, Quick Share and launcher shortcut remain separate.
- **QR-image Share and Save deliberately deferred** after investigation found no existing QR-image export infrastructure; no nonfunctional buttons were added. The existing vCard/public-key sharing capabilities are not QR-image sharing.
- Latest reported Stage 3 verification: **259/259 unit tests passed**, debug assembly passed; existing Gradle deprecation and unnecessary safe-call warnings remain non-blocking.
- **Owner-confirmed emulator acceptance (6/6):** compact row; QR screen and saved URL; independent phone scan resolving to the exact saved URL; Back navigation; saved URL update reflected in QR; original Contact QR still carries contact data rather than the Hosted Profile URL.

**Remaining V1.1 integration/release checks:** Automated instrumentation execution, accessibility/TalkBack, large-text/theme edge cases, full legacy-upgrade and backup-restore regression, physical-device checks, and release-signing verification. These are not claimed as passed by feature-level acceptance.

### Resizable Quick Card Widget (1.1.e)

- **Implemented and owner-manually accepted:** one resizable widget provides compact, standard, and expanded identity layouts; saved photo and title visibility; initials/generic fallbacks; and automatic refresh after committed profile changes.
- **Accepted interaction:** widget body opens Share. The three-dot menu offers My Card, Share, and Profile. Native launcher move, resize, and remove behavior remains launcher-managed; long-press is not intercepted by the app.
- Current unit tests cover pure model, sizing policy, menu routing, update ordering, and icon/shortcut contracts. Launcher-specific sizing, TalkBack, large text, and process-death behavior remain device verification items, not reasons to reopen accepted widget design.

## Readiness and release items

### Feature-specific requirements

- **1.1.d icon decision:** Current UI contains monochrome LinkedIn and GitHub icons and labeled text links for other platforms. The approved requirements/decision log still marks a complete recognized-platform allowlist as an open owner decision. This reconciliation records implementation/feature-acceptance status but does not expand or resolve that decision.
- **1.1.d URL safety:** Website may open HTTP/HTTPS; social and Hosted Profile links require HTTPS. Validate at the Android opening boundary and do not rewrite the exact URL text stored in the profile.
- **1.1.d validation discrepancy:** the original approved requirement says URL text must not be validated. Current implementation validates explicit Website HTTP/HTTPS and social/Hosted Profile HTTPS URLs while preserving the original entered text. Owner disposition is needed if the original no-validation wording is intended to prohibit this validation; this roadmap records the discrepancy, not a silent requirement change.
- **1.1.d data compatibility:** Schema-4 migration and automated coverage address legacy LinkedIn, GitHub, and Other Professional Link values, visibility, ordering, repeated URLs and backups; full on-device upgrade/restore regression remains pending. V1.0.0 downgrade compatibility is not promised.
- **1.1.c name limits:** Confirm the approved 200-code-point-per-component and 602-code-point generated-name limits in implementation without changing unrelated field limits.
