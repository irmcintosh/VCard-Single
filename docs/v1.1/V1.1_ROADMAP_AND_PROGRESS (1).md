### Professional Website, Social Links & Hosted Profile (1.1.d)

**Stage 1 — Data foundation: implemented; automated verification PASSED; owner/device acceptance pending.**

- **Reported production changes:** `Profile.kt`, `ProfileValidator.kt`, `ProfileCodec.kt`, `BackupDataCodec.kt`, `ProfileRepository.kt`, `ProfileViewModel.kt`, `ContactExport.kt`, and `ShareScreen.kt`.
- **Implemented according to Codex checkpoints:** schema-4 ordered, repeatable social-profile entries with stable IDs, platform, label, exact URL text, and visibility; legacy LinkedIn/GitHub/Other Professional Link migration and compatibility projection; profile and backup persistence; URL validation; repeated ordered social URL export; and Quick Share isolation.
- **Legacy scalar editor compatibility:** The current scalar controls project onto legacy slots until Stage 2; they do **not** yet provide editing for multiple entries per platform.
- **Whitespace correction:** Whitespace-only legacy social URL input removes the corresponding collection entry.
- **Test corrections:** Two schema-4 test parse calls explicitly allow arrays. Three outdated `StrictJsonTest` schema mutations were updated to schema 4 → 1, schema 4 → 5, and schema 4 plus an unknown field; a guard now verifies each mutation changes the source JSON. Strict parser default array rejection and rejection assertions remain intact.
- **Final automated verification (reported by Codex):** `:app:testDebugUnitTest` **240 passed, 0 failed, 0 errors, 0 skipped**; `:app:assembleDebug` **PASS**; both exit code **0**, using `verification/run-gradle.ps1`.
- **Known warning:** Existing Gradle 8.11.1 deprecation warning; not a failing gate.
- **Not yet verified:** Instrumentation tests, emulator/physical-device acceptance of the Stage 1 data flows, full upgrade/backup restore on device, and complete V1.1 integration/regression.

**Stage 2 — Native UI: NOT STARTED.** Implement the approved professional Website, ordered/repeatable social links, and separate **View My Online Card** presentation/editing. Link opening is external through a safe Android URI boundary; **no embedded WebView**. Preserve exact stored URL text. Recognized platform icons initially cover LinkedIn and GitHub per owner decision; other platforms remain labeled links.

**Stage 3 — Hosted Profile QR: NOT STARTED.** Add a separate QR for the Hosted Profile URL without modifying the original Contact QR or Quick Share QR behavior.

**Next gate:** Owner review/acceptance of Stage 1 automated results, followed by explicit authorization before Stage 2 implementation. Device and integration validation remain tracked separately; do not claim V1.1.d is fully complete.

## Readiness and release items

### Feature-specific requirements

- **1.1.d icon decision:** Recognized social icons initially LinkedIn and GitHub; other platform links display a text label. This supersedes the older unresolved-icon note in historical roadmap versions; synchronize the approved decision log when authorized.
- **1.1.d URL safety:** Website may open HTTP/HTTPS; social and Hosted Profile links require HTTPS. Validate at the Android opening boundary and do not rewrite the exact URL text stored in the profile.
