## 2. Executive Findings

1. **VERIFIED - DOCUMENTARY:** AGP 8.9's release table specifies Gradle **8.11.1**, JDK minimum/default **17**, Build Tools minimum/default **35.0.0**, and maximum API **35**. The same page lists patch **8.9.2**. [O1]
2. **VERIFIED - DOCUMENTARY:** Gradle 8.11.1 supports running on **Java 21**; it does **not** support running on Java 25. JBR21 can be the Gradle runtime while Studio uses its own JBR25. [O2, O4]
3. **REQUIRES VERIFICATION:** Kotlin 2.1.20 is within the current Kotlin-documented Gradle range for 8.11.1, but **AGP 8.9.2 exceeds Kotlin 2.1.20's maximum fully supported AGP 8.7.2**. This does not prove it fails; it prevents calling the entire inherited combination fully officially supported. [O3]
4. **VERIFIED - DOCUMENTARY:** Kotlin and Compose compiler plugin **2.1.20** follow the required same-version arrangement. The compiler is independent of Compose BOM versions. [O5, O6]
5. **VERIFIED - DOCUMENTARY:** Google's published BOM 2025.04.01 POM maps UI/Foundation to **1.8.0** and Material3 to **1.3.2**. Full effective dependency selection, artifact SDK requirements and API31 used paths remain unverified. [O7]
6. **VERIFIED - DOCUMENTARY:** A new ordinary phone app submitted to Google Play under the policy effective **August 31, 2026** must target **Android 16 / API 36 or higher**. `targetSdk 35` is not an adequate future Play-release baseline as of this review date. [O9]
7. **REQUIRES VERIFICATION:** Official sources conflict on AGP 8.9.x's API36 support: its release page says maximum 35, while Android's current API support table says API36 requires AGP **8.9.1** or newer. Do not silently claim either that 8.9.2 definitely supports API36 or that an AGP upgrade is unconditionally mandatory. [O1, O8]

**Conclusion:** The inherited stack remains a useful historical build-comparison candidate, not an approved VCard stack. It has a documented Kotlin/AGP tested-range gap and a Play target-policy gap. Neither historical tracker builds nor emulator boot evidence closes FG-00.

## 3. AGP, Gradle, Studio and JDK

### 3.1 AGP 8.9.2 and Gradle 8.11.1

The AGP 8.9 release page's compatibility table applies to the release family and includes the 8.9.2 patch's R8 fixes. Its minimum and default Gradle version are both 8.11.1. Thus that pair is **VERIFIED - DOCUMENTARY** from the Android plugin publisher. [O1]

Gradle 8.11.1's own historical matrix says Gradle was tested with AGP 7.3 through 8.4. That narrower historical Gradle-side test range does not invalidate Android's later explicit requirement for AGP 8.9; it is not proof that AGP 8.9.2 is in Gradle's original test suite. Likewise Gradle's embedded Kotlin 2.0.20 is the build-script Kotlin DSL implementation, not a requirement to downgrade the application's Kotlin plugin to 2.0.20. [O2]

The current Android Studio compatibility table lists **Rabbit 1 / 2026.2.1** as supporting AGP **7.1-9.4**. AGP 8.9.2 falls within that range: **VERIFIED - DOCUMENTARY** for IDE/AGP version eligibility. This does not establish a successful sync/build with the selected Gradle JDK. [O8]

### 3.2 JBR/JDK 21 versus Studio JBR25

Gradle's version-specific matrix:

| JVM | Gradle 8.11.1 conclusion |
|---|---|
| Java 17 | Supported runtime; satisfies AGP's minimum |
| Java 21 | Supported runtime (Gradle runtime support starts at 8.5) |
| Java 23 | Supported runtime |
| Java 24 or 25 | Not supported by Gradle 8.11.1 |

Android identifies JetBrains Runtime as an enhanced JDK and distinguishes Studio's runtime from the JDK chosen to run Gradle. `GRADLE_LOCAL_JAVA_HOME` selects the `java.home` value from `.gradle/config.properties`. [O4]

**INFERRED:** Existing JBR 21.0.11 is an appropriate Gradle-runtime candidate: its Java major version is supported by Gradle and exceeds AGP's minimum. The cited tables do not certify every vendor patch/build or plugin combination; that exact JBR patch still needs a build result. Do not let the IDE's bundled JBR25 become the Gradle runtime for this candidate by default.

Keep Java source/target and Kotlin JVM target **17** aligned, independent of the daemon JDK21. Kotlin documents incompatible Java/Kotlin task targets as a build error on Gradle 8+. Android Java library APIs are only a subset of desktop JDK APIs; a JDK21 daemon does not make Java21 library calls available on API31. Bytecode lowering and core-library desugaring are different concerns. [O3, O4]

No JDK, JAVA_HOME, PATH or Studio setting was changed.

## 4. Kotlin 2.1.20 and Compose

### 4.1 Kotlin Gradle plugin compatibility

The current Kotlin compatibility table gives:

| Kotlin Gradle plugin | Fully supported Gradle range | Fully supported AGP range |
|---|---|---|
| 2.1.20-2.1.21 | 7.6.3-8.12.1 | 7.3.1-8.7.2 |

Gradle **8.11.1** is within that range. AGP **8.9.2** is not. Kotlin explicitly permits trying newer AGP/Gradle releases but warns about deprecations or features not working. The 2.1.20 release notes describe full compatibility with Gradle 7.6.3 through 8.11; the current table gives the later, broader range. Both support using the 8.11 family as a candidate, and neither resolves the AGP8.9 tested-range gap. [O3, O10]

Android's separate Kotlin/D8/R8 documentation addresses class-file/shrinker support, not Kotlin Gradle plugin integration. Its fetched Kotlin2.1 row currently displays AGP text `7.4.2-8.7.2` and R8 **8.6.17**, despite the page describing the table as minimum required versions. The AGP range is ambiguous in that context. The raw HTML was independently fetched and showed the same row; this is not merely markdown conversion. [O11]

**REQUIRES VERIFICATION:** Do not interpret this unusual row as a definitive AGP upper bound for bytecode processing, or conflate it with KGP's fully tested upper bound. Verify bundled D8/R8 compatibility and Kotlin metadata handling during the eventual build, especially for dependencies compiled by newer Kotlin. No D8/R8 override or speculative compatibility fix was installed.

### 4.2 Compose compiler

Since Kotlin 2.0, Compose compiler is released with Kotlin and uses the same version. Applying `org.jetbrains.kotlin.plugin.compose` **2.1.20** alongside Kotlin Android **2.1.20** is **VERIFIED - DOCUMENTARY** version alignment. Legacy Compose compiler-extension mappings are not the configuration mechanism for this Kotlin2.x candidate. [O5, O6]

The Compose compiler is not in the BOM. A BOM is a set of coordinated library constraints, not an AGP/JDK/Kotlin compatibility certificate, and does not add libraries unless they are individually declared. [O6]

## 6. Google Play Release Target Changes

The official Android Developers policy page currently states that, starting **August 31, 2026**, new apps and updates must target **Android16 / API36 or higher**. Exceptions for Wear/Automotive/TV/XR are not applicable to an ordinary VCard phone app. Existing-app availability rules allowing API35 are not new-app submission rules. [O9]

The page mentions extensions to **November 1, 2026**. No extension eligibility or approval is established for VCard; an almost-expired extension is not a future release strategy.

Before a future Google Play release:

1. **Required policy direction:** Replace the candidate `targetSdk 35` with at least **36**, subject to owner approval and policy recheck at the actual submission date.
2. **Proposed SDK migration:** Use **compileSdk at least 36** for the API36-targeting release baseline, following Android16's documented setup of compileSdk36/targetSdk36. API37 or a future dependency could require a higher compile target; it is not required solely because the test emulator is API37. [O15]
3. **Resolve AGP documentation conflict:** AGP8.9 release notes say max35, while the current central table permits API36 from8.9.1. AGP8.10's release page explicitly supports **API36** and still requires Gradle8.11.1/JDK17 minimum. That provides a clearer release-candidate family, but an upgrade is not approved/performed and is not claimed unconditionally mandatory under the central table. [O1, O8, O16]
4. **Verify target36 behavior:** Edge-to-edge opt-out changes, predictive Back/caller navigation, UI insets and other applicable target/all-app changes need actual app tests. Android16 must be tested in addition to API31/API37 when adopting a target36 release. [O17]
5. **Preserve the proposed minimum31** unless evidence and a separate owner decision require a change.

**NOT FOUND:** An approved Play distribution decision, final release date, API36 SDK/image installation evidence in the inherited baseline, or a complete release-compatible dependency graph. Nothing was installed now. No claim is made that satisfying target API policy alone establishes full Play eligibility.

## 7. Emulator API31 and API37 Compatibility

Android documents an AVD as a device profile plus an Android system image; its API must meet the app's minimum. Google APIs images provide Google Play services; Play Store images differ and have their own limitations. [O14]

**VERIFIED - DOCUMENTARY:** API31 and API37 are appropriate lower/higher-runtime candidates for proposed minSdk31. The baseline report cites prior successful boot/adb checks for both; those observations were not repeated here.

**INFERRED:** An app compiled against35 and targeting35 can be tested on API37 using backward-compatible platform behavior, provided its manifest/ABI/dependencies permit it. Using an API37 emulator does not require compileSdk37 or targetSdk37. Conversely, that test does not verify target37-specific behavior or all Android17 changes. [O13]

If the owner later chooses to compile/target **API37**, Android's current table lists minimum AGP **9.1.1** and Studio Panda3 2025.3.3 Patch1. This is a separate toolchain decision, not a requirement to boot or test on an API37 image. [O8, O18]

Remaining runtime obligations include:

- API31: actual install/launch, API guards/desugaring, Compose and every used dependency path.
- API37: newer-platform behavior, compatible UI/test libraries and handoffs; preserve the existing protected tracker AVD/data.
- API36 if target36 is adopted: actual target-platform behavior, not merely an API37 surrogate.
- Physical Pixel and real recipient/provider/scanner behavior where required; emulator execution is not physical-device evidence.

No emulator was started, wiped, reset or modified in this review.

## 9. Remaining Risks and Next Build-Verification Action

### Remaining risks

- KGP2.1.20/AGP8.9.2 integration is outside Kotlin's maximum fully supported AGP range.
- API36 support claims for AGP8.9.x conflict across official pages; record and resolve rather than suppress an unsupported-SDK warning.
- The Android Kotlin/D8/R8 table's fetched AGP range is ambiguous; no blanket bytecode compatibility claim.
- Gradle8.11.1 cannot use Studio JBR25. A future build must capture the actual launcher/daemon/toolchain JDK, not merely its configured path.
- Inherited missing wrapper and historical/cache-heavy build results are not reproducible VCard evidence.
- BOM metadata is not effective graph evidence. Direct/transitive AAR minimums, Java APIs/desugaring, Kotlin metadata, licenses/advisories, duplicate classes/providers and release shrinker behavior remain open.
- Future QR, vCard, OpenPGP, image and native-sharing dependencies were not selected, downloaded or investigated anew here.
- API31 used paths, target36 behavior, protected runtime test boundaries, and physical-device/provider evidence remain outstanding.
- A future Play submission requires a fresh policy check; API36 is the verified minimum as of this research date, not a promise for an unspecified future date.
