## 2. Minimal Feasibility Harness Versus Production Development

A **minimal isolated feasibility harness**, if separately approved, is a disposable/synthetic artifact limited to one question (for example, whether a candidate serializer emits the approved bytes or whether a parser rejects a fixture). It is not the VCard Native app, must not contain production personal data, and cannot establish integrated navigation, storage durability, accessibility, release readiness or full gate completion unless those exact criteria are tested in the authorized scope. Do not place an isolated library result into the production dependency graph by implication.

**Production application development** includes the real app project, manifest, Gradle configuration, dependencies, Kotlin/Compose UI, data model integration, storage/recovery protocol, features, release signing and integrated tests. This sequence does not authorize or begin that work. A harness may itself contain code/tests, so it too requires explicit owner authorization; none is created here.
