## 6. Commands Executed

Paths below use environment variables to omit personal account information. `$serial` denotes the runtime-selected adb emulator identifier; its actual value is deliberately omitted. Dedicated unused console/adb ports were checked before launch and reused only after the previous emulator disconnected.

Core commands executed:

```powershell
$sdk = Join-Path $env:LOCALAPPDATA 'Android\Sdk'
$adb = Join-Path $sdk 'platform-tools\adb.exe'
$java = 'C:\Program Files\Android\Android Studio\jbr\bin\java.exe'
$tools = Join-Path $sdk 'cmdline-tools\latest'

& (Join-Path $tools 'bin\sdkmanager.bat') --list "--sdk_root=$sdk"
& (Join-Path $tools 'bin\sdkmanager.bat') --list_installed "--sdk_root=$sdk"
& (Join-Path $tools 'bin\android.exe') sdk --help
& (Join-Path $tools 'bin\android.exe') sdk install --help
& (Join-Path $tools 'bin\android.exe') "--sdk=$sdk" sdk --ignore-outdated-xmls install 'platforms/android-31@1.0.0' 'system-images/android-31/google_apis/x86_64@14.0.0'

& $java -version
& $java "-Dcom.android.sdkmanager.toolsdir=$tools" -classpath (Join-Path $tools 'lib\avdmanager-classpath.jar') com.android.sdklib.tool.AvdManagerCli list avd
& $java "-Dcom.android.sdkmanager.toolsdir=$tools" -classpath (Join-Path $tools 'lib\avdmanager-classpath.jar') com.android.sdklib.tool.AvdManagerCli list device
'no' | & $java "-Dcom.android.sdkmanager.toolsdir=$tools" -classpath (Join-Path $tools 'lib\avdmanager-classpath.jar') com.android.sdklib.tool.AvdManagerCli create avd --name VCard_API_31 --package 'system-images;android-31;google_apis;x86_64' --device pixel_5

& (Join-Path $sdk 'emulator\emulator.exe') -list-avds
& (Join-Path $sdk 'emulator\emulator.exe') -accel-check
& (Join-Path $sdk 'emulator\emulator.exe') -help-read-only
& (Join-Path $sdk 'emulator\emulator.exe') -help-no-snapshot

# Each command ran separately; actual numeric port is omitted with device identifiers.
& (Join-Path $sdk 'emulator\emulator.exe') -avd VCard_API_31 -port $verificationPort -read-only -no-snapshot -no-window -no-boot-anim
& (Join-Path $sdk 'emulator\emulator.exe') -avd Medium_Phone_API_37.0 -port $verificationPort -read-only -no-snapshot -no-window -no-boot-anim

& $adb version
& $adb devices -l
& $adb -s $serial get-state
& $adb -s $serial shell getprop sys.boot_completed
& $adb -s $serial shell getprop ro.build.version.sdk
& $adb -s $serial shell getprop ro.build.version.release
& $adb -s $serial shell getprop ro.product.cpu.abi
& $adb -s $serial shell echo FG00_API31_RESPONSIVE
& $adb -s $serial shell echo FG00_API37_RESPONSIVE
& $adb -s $serial shell cmd package path com.android.settings
& $adb -s $serial shell dumpsys activity activities
& $adb -s $serial emu kill
```

`get-state` and `sys.boot_completed` were polled every 5 seconds, with an eight-minute deadline per AVD. adb device-list serials were redacted before displaying evidence. Shell markers were used only with their corresponding AVD.

Supporting inspection commands included `Get-ChildItem`/`Get-Content` for SDK directories, launcher scripts, source properties, AVD locators/configuration and Studio build; `Get-CimInstance Win32_OperatingSystem` and filtered `Win32_Process`; `Get-PSDrive C`; `Get-NetTCPConnection` for port conflicts; `Test-Path` guards; `Get-FileHash -Algorithm SHA256` for the existing AVD configuration/locator; and `Get-Date -Format 'yyyy-MM-dd HH:mm:ss zzz'`. Official repository XML was fetched with `Invoke-WebRequest -UseBasicParsing`, selecting the exact package nodes and their revision/license/archive/dependency fields. License-text hashes were calculated with .NET SHA-1 and compared to existing license-file entries.

Emulator stdout/stderr was redirected to per-session scratch logs and inspected for errors/warnings. Both adb shutdowns returned exit 0 and device-disconnection checks returned true. Attached launcher process trees were then stopped through the tool's specific session handles; no name-based process killing was used. Final package listing, AVD listing and persisted new-configuration checks were repeated after shutdown.

## 8. Errors and Warnings

1. SDK Manager warning: `WARNING: The SDK Manager CLI tool (sdkmanager) is deprecated. Android CLI will be used instead.` The installed wrapper delegates to the already-installed Android CLI; no replacement tooling was installed.
2. The first listing filter expected traditional semicolon syntax and therefore missed the slash-form API 31 rows. A corrected listing found both packages; official XML confirmed the semicolon identifiers.
3. Initial existing-AVD hash/config reads used an assumed directory matching the full AVD name and returned `Cannot find path ... because it does not exist.` `avdmanager list avd` resolved the actual `Medium_Phone.avd` directory. Subsequent baseline/final hashes succeeded; nothing was created at the incorrect location.
4. API 31 runtime warning: `WARNING | Please update the emulator to one that supports the feature(s): Vulkan`. Boot and all requested adb checks nevertheless succeeded. No emulator update or graphics/security setting change was made. Logs identify Google SwiftShader / OpenGL ES 3.0 software rendering.
5. API 37 runtime warning: `WARNING | Emulator does not support more than 6 cores. Number of cores set to 6`. This is a runtime clamp of the existing 8-core configuration; that configuration was not edited.
6. API 31 system-image revision 14 versus bundled `Pkg.Revision=12` discrepancy remains recorded as described above.
7. API 31's image license is explicitly `android-sdk-preview-license`. Owner authorization was obtained before installation; this does not approve preview components for a future application toolchain.
8. After graceful API 31 adb shutdown/disconnection, its attached launcher session still reported running on a one-time status read. That specific attached session was stopped. The API 37 attached session was likewise cleaned up after graceful shutdown.

No installation, AVD creation, virtualization or boot blocker remains for this setup scope. No administrator privileges, unrelated dependency installation, firmware changes, Windows feature changes, SDK upgrades or Android security modifications were requested or performed.
