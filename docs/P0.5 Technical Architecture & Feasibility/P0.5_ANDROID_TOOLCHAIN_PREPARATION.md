## 10. Common Setup Failures and Safe Responses

| Symptom | Check / response; do not bypass approval or security controls |
|---|---|
| Android Studio installer or SDK download fails | Check official source, network/proxy, disk space and permissions. Record exact error; retry only within authorized scope. |
| “Not enough space” / SDK installation rolls back | Stop; capture requested/free space and selected packages. Do not delete user data, protected recovery files or other SDKs without approval. |
| Emulator is slow or will not boot | Check virtualization/hypervisor status and host resources. Record exact image/API; do not change firmware/security settings without permission. |
| Gradle JDK mismatch | Compare selected AGP/Gradle/JDK compatibility; do not upgrade arbitrary components or install global Gradle to suppress the error. |
| SDK platform/build-tools missing | Record requested package/API and selected compile target; install only after owner approves that SDK configuration. |
| `adb` device is `unauthorized` | Unlock the Pixel and review the RSA prompt on the physical device; do not accept an unknown host or use bypass tools. |
| Device is `offline` / absent | Check cable, USB mode, port and approved driver; record results. Do not disable driver-signing/security protections. |
| Duplicate classes/provider or R8 errors | Save full sanitized diagnostics and resolved graph when authorized; do not force dependency versions, especially cryptographic modules, without owner review. |
| Emulator passes but Pixel differs | Record as environment divergence; emulator success is not physical-device evidence. Do not mark the gate passed by substitution. |
| Tool installed but test/build not authorized | Stop after setup evidence; no project, build, test, experiment or phase advancement follows implicitly. |
